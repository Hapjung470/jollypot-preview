장바구니 v1 — 실물 졸리팟 장바구니 구조 기준

이 화면은 구매 플로우(옵션 시트) → 장바구니 → 주문서 사이에서 빠져 있던 단계입니다. 데이터 구조·문구는 실물 졸리팟 장바구니(2026-09-02 번들 실측)를 그대로 따르고, 배치·색은 V2 문법을 적용했습니다.

2. ★ 가장 중요한 판단 — 배송비를 그룹 머리에 올린다

실물은 배송비를 하단 요약의 "총 배송비" 한 줄로만 보여줍니다. 우리는 그룹마다 올렸습니다.
근거는 우리 주문 실측입니다 — 한 주문 = 한 딜이 94.3%이고, 딜을 2개 담으면 객단가는 +3.6%인데 배송비는 2.2배가 됩니다. 즉 장바구니에서 유저가 가장 먼저 알아야 할 것은 "무엇을 담았나"가 아니라 "배송비가 몇 번 붙나"입니다. 파트너가 둘이면 왜 배송비가 두 번인지를 그룹 머리에서 바로 읽히게 하고, 임계까지 남은 금액을 같은 자리에서 안내합니다.

3. 규칙

· 선택은 3단: 전체 선택 / 그룹 선택 / 라인 선택 — 상위 체크는 하위 전체를 따른다
· 금액은 "선택된 라인"만 계산한다. 담겨 있어도 체크가 풀리면 배송비 계산에서도 빠진다
· 배송비는 그룹별로 판정한다(파트너배송 177/180건). 그룹 선택 합계가 임계 미만이면 그룹마다 배송비가 붙는다
· 추가상품은 독립 라인이지만 본상품 아래에 들여쓰기 + 연결선 + [추가상품] 배지 + [본상품] 표기로 붙인다(면 색은 쓰지 않는다 — 장바구니는 전부 담긴 상태라 "담김"을 뜻하는 크림이 정보가 되지 못하고, 배송비 안내와 색이 경쟁한다) — 같은 배송그룹이므로 배송비를 늘리지 않는다는 사실이 시각적으로 읽혀야 한다
· 본상품을 삭제하면 딸린 추가상품도 함께 삭제한다. 추가상품만 남으면 유저는 원하지 않는 물건에 배송비만 물게 된다(실물은 남겨두지만, 이 동작은 바꾸는 것이 맞다)
· 구매 불가 상품은 지우지 않고 아래로 분리한다 — 체크 불가 · [전체 삭제] 제공. 조용히 사라지면 "내가 담았던 게 어디 갔지"가 되고, 위에 섞여 있으면 결제를 막는다
· 삭제는 확인을 받는다("선택한 상품을 삭제하시겠습니까?") · 완료 토스트로 결과를 알린다
· 무료배송 안내는 "닿을 수 있을 때"만 유도형으로 쓴다 — 남은 금액이 임계의 25% 이내 또는 5,000원 이하면 "N원 더 담으면 무료배송" + 게이지, 그보다 멀면 사실만("배송비 3,000원 / 30,000원 이상 무료배송"). 최빈 결제가 1만~2만원인데 임계가 3만~5만이라, 모두에게 유도형으로 쓰면 달성 불가 조건을 보여주며 배송비만 각인시킨다
· 수량 하한은 1 — 0으로 내려 삭제되는 방식은 쓰지 않는다(실수 삭제)

5. 개발 요건 · 확인 필요

· 화면은 장바구니 응답으로 렌더링한다. 그룹 수·라인 수·옵션 축 이름 하드코딩 금지
· 수량·삭제·선택은 라인(cartNo) 단위로 서버에 반영한다
· 적립 예정 금액(accumulationAmtWhenBuyConfirm)은 실물 요약에 있으나 이번 화면에서는 뺐습니다 — 현재 졸리팟은 적립 운영을 하지 않습니다. 운영 시작하면 요약에 한 줄 추가
· 옵션 변경(2026-09-02 추가): 라인마다 [옵션 변경] — 옵션 조합과 입력값(각인 이름)을 바꿉니다. 구현 근거: 현재 장바구니는 수량 변경 시 PUT /cart에 [{cartNo, orderCnt, optionInputs}]를 보냅니다. 즉 입력값(각인) 수정은 서버가 이미 받는 필드라 그대로 됩니다. 반면 옵션 조합(optionNo) 교체가 같은 API로 되는지는 미확인이므로, 안 되면 삭제 + 재담기(DELETE → POST /cart)로 같은 화면을 구현합니다(이때 cartNo가 바뀌므로 선택 상태·정렬 유지 처리 필요)
· ★ 품절 라인에 [다른 옵션으로 변경]을 준다: 품절은 대개 조합 하나만 막힌 것이라 색·구성을 바꾸면 되살아납니다. 지우기 전에 바꿔볼 길을 주는 편이 삭제 유도보다 낫습니다 — 바꿔서 유효해지면 구매 불가 섹션에서 원래 파트너 그룹으로 이동합니다
· 딜 마감으로 판매가 끝난 라인은 validInfo로 내려와야 구매 불가로 분리할 수 있습니다 — 딜 종료 시 상품 상태가 어떻게 바뀌는지 확인 필요
