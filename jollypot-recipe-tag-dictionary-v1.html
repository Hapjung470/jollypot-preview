09태그를 붙이는 규칙

AI가 레시피를 읽고 6칸을 채웁니다. 유저에게 태그를 고르라고 하지 않습니다.

  1. 사전에 있는 말만 붙입니다AI가 새 태그를 만들지 못합니다. 「연두부」가 사전에 있으면 붙이고, 「유부」가 없으면 못 붙입니다.
  2. 없는 말은 후보함에 쌓습니다붙이지는 못해도 버리지는 않습니다. 「유부」를 만나면 후보함에 기록합니다. 같은 말이 3건 모이면 운영자 화면에 뜹니다. 넣을지 말지는 사람이 정합니다.
  3. 레시피 3건이 모여야 화면에 나옵니다사전에 있어도 레시피가 2건이면 칩·랜딩에 안 보입니다. 3건째가 등록되는 순간 저절로 열립니다. 상품 카테고리에서 소분류 140개 중 112개(80%)가 상품 0개인 상태를 봤습니다. 같은 실수를 안 하기 위한 장치입니다.
  4. 대표 재료를 하나 정합니다제목에 나오는 재료가 대표입니다. 없으면 재료란 맨 앞. 대표만 조합 랜딩(두부조림)에 들어가고, 나머지 재료는 냉장고 매칭과 검색에만 쓰입니다.
  5. 이름을 통일해서 저장합니다「다진마늘」이 들어오면 태그는 「마늘」로 붙입니다. 화면에는 작성자가 쓴 「다진마늘」이 그대로 보입니다.
  6. 확신이 낮으면 비웁니다억지로 채우지 않습니다. 비어 있는 칸은 나중에 채울 수 있지만, 잘못 붙은 태그는 사용자가 먼저 발견합니다.
  7. 태그를 지우지 않고 넘겨보냅니다「유아식」을 「아기」로 합치더라도 옛 이름을 지우지 않습니다. 사전에 「유아식 → 아기」를 남기고, 옛 주소로 들어오면 새 페이지로 보냅니다. 안 그러면 검색에 걸려 있던 페이지가 끊깁니다.

유저가 직접 쓴 레시피도 같습니다. 지금 레시피 작성 화면에는 태그 입력칸이 없습니다(이미지·제목·설명·시간·인분·칼로리·재료·조리순서). 여기에 태그 칸을 새로 만들지 않습니다. 재료와 조리 순서를 이미 입력했으니 AI가 읽을 재료는 충분합니다. 예외는 07번의 「누가 먹나」 칩 하나뿐입니다.

냉장고 기능이 이 사전을 그대로 씁니다. 스코프 03의 「이 재료로 만들 수 있어요」는 보유 재료와 레시피 재료를 맞춰봐야 하는데, 이름이 통일돼 있지 않으면 냉장고의 「계란」이 레시피의 「달걀」을 못 찾습니다. 재료 사전을 따로 만들면 두 벌을 계속 맞춰야 합니다.

지금 막혀 있는 것

  • 「다 있어요」 판정이 불가능합니다. 레시피 158건 전부 재료가 「필수」로 표시돼 있습니다(158/158). 소금·후추까지 냉장고에 있어야 통과합니다. 추출 단계에서 필수·선택을 갈라야 합니다.
  • 난이도가 변별력이 없습니다. 158건 전부 「보통」입니다. 필터로 쓸 수 없습니다.
  • 채널 주소가 비어 있습니다. 채널명은 135건 있는데 주소는 0건입니다. 「누구 레시피」 랜딩에서 원작자로 보내줄 곳이 없습니다.
  • 검색이 양념까지 읽습니다. 「소금」을 치면 158건 중 60건이 나옵니다. 「조림」을 치면 4건뿐입니다 — 제목에 그 글자가 든 것만 나옵니다.

확인이 필요한 것

  • 백엔드(긱) — 태그 테이블·후보함·검수 큐 추가 견적. 데이터 모델 변경이라 별도 산정이 필요합니다.
  • 백엔드(긱) — 재료 필수·선택 구분을 추출 단계에서 넣을 수 있는지.
  • 법무 — 프로그램 이름(편스토랑·흑백요리사·냉장고를부탁해) 상표. 인물 이름은 확인 완료.
  • 기획 — 158건 일괄 태깅 후 전수 검수 일정. 자동 태깅 정확도는 이 검수 결과로 정합니다.

단계

  1. 사전 등록 + 158건 일괄 태깅6칸 값을 어드민에 넣고, 기존 158건에 붙인 뒤 전수 검수합니다. 이 단계에서 이름 통일 표가 완성됩니다.
