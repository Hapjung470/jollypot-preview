v6 수정 — 상태 화면 폭 점프 (2026-08-13)

증상: 상단 토글로 특이케이스(실패/중단) 화면을 열면 콘텐츠 폭이 넓어지고, 닫으면 되돌아왔다.
실측: 정상 360px → 상태 표시 375px → 복귀 360px (데스크톱 기준 15px 점프, 5개 상태 전부 동일).
원인: 상태 표시 중 배경 스크롤을 잠그려고 overflow:hidden을 걸면 세로 스크롤바가 사라지면서 레이아웃 가용 폭이 스크롤바 두께만큼 넓어진다. 화면 자체의 폭 설정 문제가 아니라 스크롤바 소실이 원인.
조치: ① html{scrollbar-gutter:stable}로 스크롤바 자리를 항상 확보 — 잠금 여부와 무관하게 폭 고정 ② 전체화면 상태의 정렬 문법을 inset:0 + margin auto에서 하단 고정바·시트와 동일한 left:50% + translateX(-50%)로 통일 — 정렬 규칙이 화면마다 다르면 반올림 차이로 1px 어긋남이 생긴다.

개발 요건: 모달·바텀시트로 배경 스크롤을 잠글 때는 스크롤바 폭 보정을 반드시 함께 처리한다(스크롤바 거터 또는 동일 폭 패딩 보정). 실제 앱(웹뷰)에서는 오버레이 스크롤바라 증상이 안 보일 수 있으나, PC 웹에서는 모달을 열 때마다 화면이 흔들린다.

v5 변경 (2026-08-13)

동의 문구에서 연령 확인 부분 제거 — "본인은 만 14세 이상이며, 주문 내용을 확인하였습니다." → "주문 내용을 확인하였으며, 결제에 동의합니다."

근거를 둘로 나눠 판단했다.
• 연령(만 14세) 확인: 개인정보보호법상 만 14세 미만은 법정대리인 동의가 필요해 가입 시점에 확인하는 것이 원칙. 가입 단계에서 이미 받는다면 주문마다 반복할 실익이 낮다. 단, 비회원 주문을 허용하면 연령 확인 근거가 사라지므로 이 경우엔 문구가 필요하다.
• 주문 내용 확인·결제 동의: 전자상거래법상 사업자는 소비자가 청약 내용을 확인·정정할 수 있는 절차를 제공해야 한다. 문구 자체가 법정 필수는 아니지만 확인 절차를 거쳤다는 표시로 실무에서 널리 쓰이므로 유지 권장.
• 레퍼런스 확인: 우리가 참고한 오늘의집(버킷플레이스)은 이 문구를 그대로 노출하고 있다 — 즉 업계에서 빼는 것이 표준은 아니다.

이 변경은 법무 검토 대상이다. ①비회원 주문 허용 여부 ②가입 시 연령 확인 절차 유무 두 가지가 확정돼야 최종 판단이 가능하며, 둘 중 하나라도 미비하면 연령 문구를 복원해야 한다.

v4 변경 (2026-08-13)

① "주문상품" 붙여쓰기(할인혜택·결제수단과 표기 통일) ② 총액 하단 캡션 2줄 제거 — 퀵계좌 할인 예고 + 적립 예정. 근거: 같은 혜택이 화면에서 3번 반복(히어로 스트립 · 총액 캡션 · 하단 절약 스트립)되어 결제 직전 정보 밀도만 높였다. 혜택 고지는 수단 선택 시점(히어로 스트립)과 결제 직전(하단 절약 스트립) 두 지점으로 충분.
참고: 제거된 캡션 중 "퀵계좌이체로 결제하면 ~" 문구는 다른 수단 선택 시에도 퀵계좌를 상기시키는 유일한 장치였다. 유도 강도가 필요해지면 하단 절약 스트립 문구에 조건부로 합치는 방식을 검토(단, 확정 전 금액을 약속하지 않는 원칙은 유지).

v3 — 결제 실패/중단 상태 5종 (2026-08-13)

설계 원칙: 실패 화면이 답해야 할 질문은 "왜 실패했나"가 아니라 "내 돈이 나갔나" + "이제 뭘 하면 되나" 두 가지다. 그래서 모든 실패 화면에 "결제 금액은 청구되지 않았어요" 확인 배지를 넣고(청구 여부가 불확실한 3번은 제외), 다음 행동을 1순위 버튼으로 둔다.

#상태형태핵심 설계
1수단 거절(한도·잔액·정지)시트주문 정보를 잃지 않게 시트로. 퀵계좌이체 대안 카드를 1순위로 제시(0.5% 할인 포함) — 카드 거절 순간은 퀵계좌 전환의 최적 지점. 오류코드/주문번호는 접힘에 넣어 CS용으로만.
2결제 중단(사용자 취소·앱 미복귀)시트실패가 아니므로 에러 컬러 사용 금지. 중립 아이콘 + "주문 내용은 그대로 있어요" + [이어서 결제하기] 1버튼. 취소를 사고처럼 다루면 고객이 불안해진다.
3결과 확인 중(타임아웃·응답 없음)전체 화면가장 위험한 상태. 결제 여부가 불확실하므로 절대 "실패"라고 단정하지 않는다. 청구 안내 배지도 넣지 않는다. 재시도 버튼을 주지 않고 "다시 결제하지 말아주세요"를 명시 — 여기서 재시도가 이중결제의 주 원인. 결과는 알림/주문내역으로.
4결제 중 품절전체 화면재시도가 무의미하므로 재시도 버튼 없음. 어떤 상품이 품절인지 표시하고 [재입고 알림] / [장바구니로]. 다품목 주문이면 "품절 상품 빼고 주문하기"를 1순위로.
5시스템·네트워크 오류시트우리 잘못이므로 사과 톤 + 청구 안내 + [다시 시도하기]. 고객센터는 보조.

시트 vs 전체 화면 기준: 같은 주문으로 복구 가능하면 시트(주문 컨텍스트 유지 = 재시도 마찰 최소), 주문 상태 자체가 바뀌었으면 전체 화면(품절·확인중). 전체 화면으로 튕기면 "처음부터 다시"라는 인상을 줘 이탈이 커진다.

개발 요건 (상태)

• PG 응답코드 -> 5개 상태 매핑표 필요(거절/취소/타임아웃/재고/시스템) · 미분류 코드는 5번(시스템 오류)로 폴백
• 3번은 결제 결과 폴링 + 서버 웹훅 병행 · 사용자가 화면을 닫아도 서버가 결과를 확정하고 알림 발송 · 동일 주문 재결제 요청 차단(멱등키)
• 1번 대안 카드는 이미 퀵계좌이체로 결제하다 실패한 경우 노출하지 않는다(다른 수단 제안으로 교체)
• 오류코드는 화면에 노출하지 않고 접힘 안에만 · CS 상담용 주문번호는 항상 포함

• 주문 상품 접기: 헤더의 ∧로 접기(재확인 니즈만 대응, 기본 펼침).
• 절약 스트립(에이블리 참고): CTA 직전 "지금 주문하면 2,700원을 아껴요" — 할인 합계(쿠폰+적립금)가 0원이면 미노출. 색은 핑크가 아니라 크림(가이드 면 문법).
• 적립 예정 19P: 금액 행에서 빼고 오늘의집처럼 총액 아래 소형 캡션으로 강등 — 소액일 때 행으로 노출하면 "적립이 의미 없다" 신호가 됨.

CX 제안 — 결정 필요

• 배송비 3,000원의 위치: 결제 직전에 처음 보이면 이탈 요인. 상품 카드의 "파트너 배송" 태그 옆에 "배송비 3,000원"을 미리 표기하거나, 장바구니 단계에서 노출 권장.
• 현금영수증: 가상계좌 선택 시 현금영수증 신청 UI(오늘의집 참고)가 실결제엔 필요 — 이번 프로토엔 미포함, 개발 범위 판단 필요.
