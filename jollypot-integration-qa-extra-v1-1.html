v1-1 재검증 — 바로잡은 것과 더한 것

v1의 숫자 중 일부는 화면을 다 그린 뒤에 잰 값이었습니다. 카톡 미리보기는 원본 HTML만 읽고, 문구는 출처가 앱인지 서버인지 인스타인지 갈라 봐야 했습니다. 그래서 원본 HTML, 앱 스크립트 전체(78개 파일), 관리자 스크립트, 서버 응답을 다시 받아 대조했습니다.
구분내용
뺌v1 C25 인스타 「Instagram에서 보기 링크를 이용해 주세요.」: 우리 앱·관리자 코드와 서버 응답 어디에도 없습니다. 인스타 퍼가기 창 안에 인스타가 넣는 문구라 개발사가 고칠 수 없습니다.
옮김v1 C32 가입 필수 항목: 샵바이 쇼핑몰 설정(가입 항목 설정)에서 생년월일·성별·전화번호·휴대폰이 「필수」로 되어 있었습니다. 개발사 코드가 아니라 우리 샵바이 관리자에서 바꿀 일이라 내부 확인 D6으로 옮겼습니다.
바로잡음C3 글꼴: 우리 서버 파일이 아니라 jsDelivr에서 받는 전체 글꼴입니다. 글자를 먼저 기본 글꼴로 보여 주는 방식이라 글꼴 때문에 글자가 늦게 뜨지는 않습니다. 가장 큰 낭비는 1254px 캐릭터 그림을 37·74px로 쓰는 것(759KB, 캐시 없음)입니다.
바로잡음C4 썸네일: 「이미 깨진 썸네일」 근거를 다시 확인하지 못했습니다. 유튜브 주소 123개를 모두 열어 보니 깨진 것은 0개라 하로 낮추고 예방 요청으로 바꿨습니다.
바로잡음C5 컬렉션 미리보기: 카톡이 읽는 원본 기준으로는 제목이 「컬렉션 | JollyPot」도 아니고 「JollyPot」뿐입니다. 이 화면만 검색 노출 허용인 것도 함께 적었습니다.
바로잡음C26 「완료되면 알려드릴게요」: 저장 목록의 상태 카드로 알린다는 것을 코드에서 확인했습니다. 질문 대신 우리가 정한 문구 「다 되면 저장 목록에 나타나요」로 바꿔 달라는 요청으로 고쳤습니다.
보탬C23·C24·C21: 「스크랩북」이 2곳 더 있었습니다(브라우저 기본 확인창 포함). 「컬렉션을 삭제했습니다.」는 서버 응답 문구로 보입니다. 없는 주소 화면 합쇼체도 더했습니다. 영어 화면읽기 안내는 관리자가 아니라 회원 앱 공통 코드에 있습니다.
올림C27 타임특가: 중→상. 세 탭 모두 서버 오류(DB_QUERY_FAILED)인데 「상품이 없습니다」로 보입니다.
새로C34~C42 9개: 댓글 실명 표시(상), 보안 헤더, 개발 서버 연결, 분석 이벤트 없음(이상 중), 공용 토큰 만료 없음, 검색 노출 설정, 올린 사진 원본 그대로, 같은 요청 반복, 개발용 콘솔 기록(이상 하).
확인 후 문제 아님관리자 스크립트 소스맵(.map)이 200으로 응답해 원본 코드 공개를 의심했습니다. 받아 보니 없는 주소에도 관리자 첫 화면을 돌려주는 동작이라 문제가 아니었습니다. 앱 스크립트에서 비밀 키(AI·클라우드 키) 형태도 찾지 못했습니다.

C1에서 아이디 원문이 나가는 회원(아이디 「te」로 시작·6자, 레시피 10개)은 개발사 시험 계정으로 보입니다. 맞다면 오픈 전에 지우면 되고, 실제 회원이면 C1을 더 서둘러야 합니다.
D6가입 필수 항목·닉네임은 우리 샵바이 쇼핑몰 설정
샵바이 가입 항목 설정이 이름·이메일·생년월일·성별·전화번호·휴대폰 「필수」, 닉네임 「사용 안 함」입니다. 쇼핑몰 주소가 jollypot.co.kr이라 지금 쇼핑몰과 같은 설정일 수 있습니다. 바꾸면 그쪽 가입에도 영향이 가는지 먼저 확인해야 합니다. 닉네임을 켜면 C34(댓글 실명)도 함께 풀 수 있습니다.
D7관리자 계정 보호
관리자 화면은 인터넷 어디서나 열리고, 개발사가 준 관리자 비밀번호는 추측하기 쉬운 형태입니다. 2단계 인증도 없습니다. 운영 전환 때 비밀번호 교체와 접속 제한(사무실 IP 등)을 요청하는 것을 권합니다.
D8분석 계정 주인 확인
앱에 들어 있는 GA(G-75ZKPYWQ03)·GTM(GTM-M6PHSRQX)이 레몬트리 계정인지, 운영과 같은 속성인지 확인이 필요합니다. 같다면 지금까지의 개발·QA 방문이 섞여 있습니다(C37).
D9개인정보 보호책임자 전화번호
샵바이 쇼핑몰 기본 정보의 「개인정보 보호책임자 전화번호」가 비어 있습니다. 방침 화면에 따로 적혀 있는지 함께 확인해 주세요.
D10분석 이벤트 목록 정하기
C38에 개발사가 답하면 레몬트리가 이벤트 목록을 줘야 합니다. 저장·링크 만들기 성공과 실패·컬렉션·공유·쿠팡 이동·댓글·상품 담기를 권합니다. 「본 사람 중 저장하는 비율」, 「링크 만들기 성공률」을 오픈 첫 주부터 보려면 출시 전에 들어가야 합니다.

이상 없음을 확인한 것

  • 레시피를 보고 뒤로 가면 홈 스크롤 위치가 그대로입니다.
  • [저장]·[댓글 등록]을 빠르게 두 번 눌러도 하나만 생깁니다.
  • 댓글에 HTML·스크립트를 넣어도 글자로만 보이고 실행되지 않습니다.
  • 인터넷이 끊긴 상태에서 저장하면 「레시피를 저장하지 못했어요.」가 뜹니다.
  • 일반 회원 로그인이나 로그인 없이 관리자 기능을 부르면 모두 401로 막힙니다.
  • 다른 회원 컬렉션에 레시피를 넣는 요청을 보내면 403 「내 컬렉션만 수정할 수 있습니다」로 막힙니다.
  • 조회 요청에 다른 회원 번호를 끼워 넣어도 무시하고 내 것만 줍니다.
  • 페이지 언어 표시(ko)·파비콘·앱 설치 정보(manifest)가 들어 있습니다.
  • 회원 탈퇴 기능이 마이페이지 정보 수정에 있습니다(앱스토어 심사 요건).
  • 레시피 상세 원본 HTML에 제목·사진·설명과 레시피 구조화 데이터가 들어 있습니다.
  • 앱 스크립트·스타일 파일은 1년 캐시와 압축으로 내려갑니다. 앱 스크립트 원본 지도(소스맵)는 공개되어 있지 않습니다.
  • 앱 스크립트에서 AI·클라우드 비밀 키 형태를 찾지 못했습니다(공용 토큰은 C36).

어떻게 쟀나

  • 화면 전수: 앱 주소 69개 중 실제로 열리는 화면 45개를 로그인 전·후로 한 번씩 열고 다음을 셌습니다. 글자 색과 바탕의 대비, 가이드 밖 색, 굵기 700, 12px보다 작은 글자, 44px보다 작은 누르는 곳, 이름 없는 버튼, 오류 응답, 공유 미리보기 정보, 받은 용량입니다.
  • 느린 망: 내려받기 400kbps·지연 0.4초로 홈과 레시피 상세를 열어 글자가 뜰 때까지의 시간을 쟀습니다.
  • 개인정보: 로그인하지 않은 상태로 조회(GET)만 했습니다. 이름 값은 저장·출력하지 않고 개수만 셌습니다.
  • 문구: 화면과 알림에 나온 글자 1,925개를 모아 말투·마침표·옛 이름을 분류했습니다. 레시피 본문 말투는 원본 144개 전체를 셌습니다.
  • 검색: 같은 뜻의 검색어를 바른 표기와 틀린 표기로 한 쌍씩 넣어 결과 수를 비교했습니다.
