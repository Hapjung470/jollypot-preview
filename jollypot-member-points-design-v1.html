졸리팟 회원 구조와 활동 적립금 설계
댓글·후기를 쓴 사람에게 쇼핑 적립금을 줄 수 있나

2026.11.02 · 개발 서버 실측 · 샵바이 공식 서버 API 명세(manage·member·promotion) 확인
결론 3줄
  1. 됩니다. 샵바이에 「적립금 지급하기」 공식 API가 있습니다. 회원번호와 금액, 만료일만 넣으면 즉시 지급됩니다. 받은 적립금은 샵바이 마이페이지에 보이고, 결제 때 그대로 쓸 수 있습니다. 결제 쪽은 손댈 게 없습니다.
  2. 회원은 이미 하나입니다. 개발 서버는 샵바이 로그인으로 사람을 알아보고, 레시피에 샵바이 회원번호를 붙여 저장합니다. 레시피를 올린 A와 물건을 산 A는 같은 회원번호라, 따로 회원 DB를 만들 필요가 없습니다. 샵바이 = 회원·돈 원장, 졸리팟 DB = 활동 원장으로 나누면 됩니다.
  3. 다만 「댓글」에는 주지 않기를 권합니다. 댓글은 가장 쉽게 부풀릴 수 있고, 졸리팟에 남는 가치가 작습니다. 돈은 사진이 있는 요리 후기와 남이 저장한 레시피에 겁니다. 오늘의집처럼 사진 콘텐츠가 쌓이는 쪽입니다.

1. 지금 구조 — 개발 서버 실측

확인한 것결과
로그인샵바이 로그인(oauth/token)으로 받은 토큰을 졸리팟 서버에 함께 보냅니다. 졸리팟 서버는 그 토큰으로 샵바이 회원 정보(/profile)를 확인합니다.
레시피에 붙는 사람 정보ownerMemberNo·memberNo(샵바이 회원번호), memberId(아이디), memberName(이름)
닉네임샵바이 회원 정보의 닉네임 칸을 그대로 씁니다(중복 확인도 샵바이)
마이페이지 적립금개발 서버 화면에 /mypage/accumulations가 이미 있고, 샵바이 적립금 API를 그대로 읽습니다

대표님 짐작이 맞습니다. 졸리팟 서버에는 회원 DB가 따로 없고, 샵바이 회원번호를 열쇠로 씁니다. 이 구조는 맞는 방향입니다. 회원을 두 군데 두면 탈퇴·개인정보·로그인을 두 번 관리해야 하기 때문입니다.

샵바이 — 회원·돈 원장
  • 로그인·회원가입·탈퇴
  • 이름·연락처·주소(개인정보)
  • 닉네임·마케팅 수신 동의
  • 주문·결제·쿠폰·적립금
졸리팟 DB — 활동 원장
  • 레시피·요리 후기·댓글·저장·신고
  • 모든 기록에 샵바이 회원번호만 붙임
  • 보상 장부(무엇에 얼마를 줬나)
  • 공개 프로필은 닉네임·사진만
고칠 점 하나. 개발 서버는 레시피 기록에 회원의 이름(실명)까지 복사해 둡니다. 화면에는 안 나오더라도, 개인정보가 콘텐츠 DB로 퍼지면 탈퇴·유출 때 지울 곳이 늘어납니다. 활동 기록에는 회원번호만 두고, 이름이 필요하면 그때 샵바이에서 읽게 하는 게 맞습니다.

2. 적립금 지급 — 샵바이 공식 API

API (server, manage 명세)하는 일졸리팟 쓰임
POST /profile/accumulations
적립금 지급하기		회원번호·금액·만료일·사유·외부 키를 넣으면 즉시 지급후기 승인 시 지급. 외부 키에 후기 번호를 넣어 두 번 지급 방지
DELETE /profile/accumulations
적립금 차감하기		회원번호·금액·사유로 차감. 보유액보다 많으면 실패부정 후기가 지워졌을 때 회수
GET /accumulations/settlement
지급·차감 이력		기간별 지급·차감·롤백 이력월 정산·회계 보고
POST /coupons/issues
회원번호로 쿠폰 발급 (promotion 명세)		만들어 둔 쿠폰을 특정 회원에게 지급「첫 후기 쿠폰」처럼 적립금 대신 쓸 때

지급 사유는 회원의 적립금 내역에 「레시피 후기 작성 적립」처럼 남습니다. 지금은 관리자 화면에서 엑셀로 한 번에 지급(최대 1만 건)하는 방법도 있습니다. 하지만 API를 쓰면 사람 손이 필요 없습니다.

흐름 — 결제는 손대지 않습니다

1 활동A가 사진 요리 후기를 올림 (졸리팟 DB, 회원번호 붙음)
2 대기보상 장부에 「대기」로 기록. 7일 동안 신고·삭제를 봄
3 지급졸리팟 서버가 샵바이 지급 API 호출 (외부 키 = 후기 번호)
4 확인A는 마이페이지 적립금에서 확인 (이미 있는 화면)
5 사용샵바이 결제 화면에서 적립금으로 결제

지급 API는 졸리팟 서버에서만 부릅니다. 앱이나 웹 화면에서 부르면 열쇠(systemKey)가 노출돼 누구나 적립금을 찍어낼 수 있습니다.

AI 레시피 등록에 바로 돈을 주면, 우리가 AI 비용과 적립금을 동시에 내는 구조가 됩니다. 「다른 사람이 저장한 레시피」에만 주면 쓸모 있는 레시피만 돈을 받습니다.

금액 — 시험값입니다

국내 레시피·식품몰의 후기 적립금 공식 금액은 이번에 확인하지 못했습니다. 그래서 아래는 4주 시험으로 정할 출발값입니다.

  • 사진 요리 후기 500원 · 첫 후기는 1,000원 쿠폰
  • 남이 5번 저장한 레시피 1,000원 (레시피당 1회)
  • 한 사람 월 상한 3,000원, 만료 30일. 만료가 짧아야 「쓰러 오는」 이유가 됩니다

판정 지표는 둘입니다. 후기를 쓴 사람의 30일 안 재구매율, 그리고 쓰지 않은 사람과의 차이입니다. 차이가 적립금보다 작으면 접습니다.

4. 부풀리기를 막는 규칙 7개

  1. 바로 주지 않고 7일 뒤 줍니다. 그동안 신고되거나 지워지면 지급하지 않습니다.
  2. 외부 키로 한 번만 줍니다. 같은 후기 번호로는 두 번 지급되지 않습니다.
  3. 같은 레시피 후기는 1회, 하루 1건, 월 상한 3,000원.
  4. 사진 필수, 같은 사진 재사용 차단. 사진 지문 비교로 막습니다.
  5. 구매 이력이 1번 이상인 회원만 받습니다. 샵바이 주문 기록으로 확인합니다. 가짜 계정으로 적립금을 모으는 걸 막고, 이미 산 사람이 다시 오게 합니다.
  6. 지운 후기는 남은 적립금에서 회수합니다. 이미 썼으면 회수가 실패하므로 그냥 둡니다. 1번 규칙 덕에 드뭅니다.
  7. 탈퇴 회원은 매일 맞춥니다. 샵바이 탈퇴 회원 조회(/members/expelled-members)로 활동 기록을 익명 처리합니다.

5. 법·회계에서 챙길 것

후기 보상 표시. 공정위 추천·보증 심사지침은 대가를 받고 쓴 후기에 그 사실을 표시하게 합니다. 다만 「모든 사람에게 차별 없이 소액을 주고, 소비자가 그 사실을 쉽게 알 수 있으면」 따로 표시하지 않아도 된다는 해설이 있습니다. 안전하게 가려면 아래 셋을 지킵니다.

  • 적립금 정책을 후기 쓰기 화면에 분명히 적습니다.
  • 적립금을 받은 후기에는 「적립금 지급 후기」 표시를 붙입니다.
  • 좋은 말·별점과 상관없이 줍니다. 칭찬한 후기에만 주면 문제가 됩니다.

회계. 지급한 적립금은 쓰일 때 매출이 줄어드는 구조라, 지급액·사용액·소멸액을 매달 따로 봐야 합니다. 지급·차감 이력 API로 월 보고서를 자동으로 뽑을 수 있습니다. 처리 방식은 회계 담당 확인이 필요합니다.

위 법 해석은 언론 해설 기준입니다. 시작 전에 공정위 지침 원문으로 확인해야 합니다.

6. 개발사에 줄 요구사항

#요구사항
1회원 원장은 샵바이 하나. 졸리팟 DB의 활동 기록에는 샵바이 회원번호만 저장 (이름·연락처 복사 금지)
2보상 장부 테이블: 회원번호 · 활동 종류 · 활동 번호 · 금액 · 상태(대기/지급/회수/취소) · 외부 키 · 지급 일시
37일 대기 후 지급하는 예약 작업 + 샵바이 POST /profile/accumulations 호출 (서버에서만)
4삭제·신고 확정 시 DELETE /profile/accumulations 회수
5규칙 값(금액·상한·대기일·대상)은 운영 설정에서 바꿀 수 있게 — 시험하며 조정
6관리자 화면: 보상 장부 목록 · 수동 지급/회수 · 월 합계
7샵바이 서버 API 앱에 적립금 권한 추가 (레몬트리가 워크스페이스에서 승인)

순서 제안: 출시 때는 2번 장부 테이블과 1번 원칙만 넣고 지급은 끕니다. 후기가 쌓이기 시작하면 4주 시험으로 켭니다. 장부를 처음부터 두면, 나중에 「출시 이후 쓴 후기」에 소급 지급도 할 수 있습니다.

7. 정해 주실 것

  1. 보상 대상: 사진 요리 후기 + 저장된 레시피로 갈지, 댓글도 넣을지.
  2. 받는 사람: 구매 이력 1회 이상 회원만으로 제한할지.
  3. 시점: 출시 때는 장부만 두고, 지급은 출시 뒤 시험으로 켤지.
