결제수단 선택 v1 — 설계 근거 (2026-08-13)

토스 목업 피드백 4건 + 베이비빌리 레퍼런스 3종 기반. 디자인 가이드 v2.0.4 준수(피치크림 면 · 뉴트럴 선 · 딥그린 확정 · 오렌지 액션).

피드백반영
01 혜택 영역 UI 구분간편결제 카드에 노른자 "혜택" 배지(칩 계열 #FFC520) + 선택 수단 아래 피치크림 혜택 패널. 배지=발견, 패널=내용으로 역할 분리. 베이비빌리의 회색 박스 대신 브랜드 웜 톤.
02 라디오 · 토스→네페 순 · 토스 기본간편결제 카드 안에 라디오 2행(토스페이 기본 선택). 토스 선택 시에만 "계좌 결제 시 0.5% 즉시 할인" 패널 노출. 네이버페이는 확정된 혜택이 없어 패널 미노출(빈 혜택 문구는 신뢰 손상).
03 가상계좌 배치A안(추천) = 플랫 리스트 최하단. 수단이 4개뿐이라 접기는 절약 효과가 작고, 무통장 고객(선물·현금 구매)은 습관적 사용자라 숨기면 이탈 위험. B안(접힘)은 상단 토글로 비교 가능 — 수단이 6개 이상으로 늘면 B안 전환 권장. 가상계좌 선택 시 입금 안내 인라인 노출.
04 다음에도 사용수단 목록 하단 체크박스(기본 ON, 딥그린). 문구는 "~할게요"로 졸리팟 보이스 통일.

CX 설계 포인트

• 선택 상태 = 딥그린(라디오·카드 보더·체크박스) — 가이드의 "확정·분류" 역할. 결제하기 CTA만 오렌지로 남겨 마지막 행동이 화면에서 유일한 액션 컬러가 되게 함.
• 총 결제 금액 아래 할인 예고 캡션: 토스 계좌 결제 예상 할인(36,600×0.5%≈183원)을 미리 보여줘 혜택 배지→결제 완료까지 기대가 이어지게 함. 수단 변경 시 캡션 자동 갱신.
• 혜택 금액을 총액에 선반영하지 않음 — 할인은 토스 결제창에서 확정되므로 선반영 시 금액 불일치 클레임 위험. "약 ~원 추가 할인" 예고만.
• 주문 컨텍스트는 상단 1줄 요약(상품·배송지·도착일)으로 압축 — 결제 단계에서는 결정만 남기고 정보는 걷어냄.

정책·개발 확정 필요

• 토스페이 0.5% 할인의 정확한 조건·상한(최대 할인액, ID당 횟수) — 토스 계약 조건 확정 후 문구 반영
