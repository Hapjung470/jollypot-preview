졸리팟 디자인 가이드

UI/UX 디자이너 · 개발자용 디자인 시스템 문서 Version 2.0.6 | 2026.10.28 | 색·모양 결정표(§4.0) 신설 · 문장 사이 모순 정리

⚠ 이 가이드를 읽는 사람·AI 모두: §4.0 「색·모양 결정표」가 이 문서의 다른 모든 문장보다 우선합니다. 표에 없거나, 표와 시안(프로토타입)이 다르면 추측하지 말고 문의해 주세요.

1. 브랜드 철학

졸리팟은 "따뜻한 살림 큐레이션 플랫폼" 을 지향합니다.

  • 친근함: 내 부엌 같은 따뜻함
  • 차별화: 한국 푸드 플랫폼에서 흔하지 않은 주황 + 딥그린 조합
  • 기능성: 감성과 전환을 분리. 브랜드 컬러와 액션 컬러의 역할을 명확히 구분
  • 위계: 한 화면에서 "어디를 먼저 볼지"가 컬러와 타이포그래피 두 축으로 결정됨

핵심 원칙: 노른자 옐로우는 브랜드 IP, 오렌지는 누르는 것(액션), 딥그린은 고른 상태·완료. 세 컬러의 역할을 절대 섞지 않습니다.

1.1 차별화 근거 (v2.0에서 갱신)

v1.1은 "빨강/순주황 단독 사용 금지 — 쿠팡/배민 톤" 을 명시했습니다. v2.0의 오렌지는 이 원칙과 충돌하지 않습니다.

브랜드 색상각(Hue) 구성
쿠팡 0° 안팎 (빨강) 빨강 단독
배민 175° (민트) 민트 단독
컬리 300° 안팎 (보라) 보라 단독
졸리팟 v2.0 16° (주황) 주황 + 딥그린 158° 페어

빨강(0°)과 주황(16°)은 구분되며, 결정적으로 단독이 아니라 딥그린과 짝을 이룹니다. 국내 푸드 플랫폼에 이 조합은 없습니다.

선은 뉴트럴, 면은 웜: 보더·구분선은 회색 계열로 통일합니다. 피치크림(웜) 면 위에 웜 선을 겹치면 경계가 흐려집니다 — KS가 피치크림 카드에 회색 선을 쓰는 이유. 보더가 하나뿐인 이유: 초안에서는 카드용·강조용을 나눴으나, 명암비를 계산해보니 초안값(#F0E2D0)이 피치크림 위 1.18:1, 흰색 위 1.27:1 로 양쪽 모두 사실상 보이지 않았습니다. #CCCFD4는 피치크림 위 1.45:1, 흰색 위 1.56:1 로 두 배경 모두에서 경계가 살아나 하나로 통합했습니다. 카드가 흰색이든 피치크림이든 같은 보더를 쓰면 됩니다.

3. 타이포그래피

3.1 폰트 — Pretendard Variable

<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable.min.css">

body {
  font-family: 'Pretendard Variable', Pretendard, -apple-system,
               BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif;
  -webkit-font-smoothing: antialiased;   /* 필수 */
  -moz-osx-font-smoothing: grayscale;
}

⚠ Kitchen Stories의 폰트는 차용할 수 없습니다. KS는 ttcommons(UI)와 aime(레시피 제목)를 쓰는데, 둘 다 한글 글리프가 없는 라틴 전용 폰트입니다. 따라서 타이포그래피는 한글 환경에서 검증된 Pretendard Variable을 채택합니다.

⚠ 선언만 하고 로드하지 않으면 무의미합니다. 폰트 스택에 이름만 넣으면 시스템 폰트로 폴백되고, Pretendard보다 x-height가 작아 같은 px에서도 작아 보입니다. 반드시 위 <link>로 실제 로드하세요.

-webkit-font-smoothing: antialiased도 필수입니다. 기본값(서브픽셀 AA)은 획 주변에 색 성분을 더해 같은 굵기라도 두껍게 보입니다. Kitchen Stories와 오늘의집 모두 이 값을 명시적으로 지정합니다.

3.2 자간

letter-spacing: -0.3px;   /* 제목·본문 공통 */

한글은 라틴보다 글자 폭이 넓어 기본 자간이 성기게 보입니다. -0.3px이 검증된 값이며, -0.5px 이하로 조이면 답답해 보입니다.

3.3 스케일

L1  섹션 헤더        19px / 600 / 잉크
L2  서브섹션 헤더     17px / 600 / 잉크
L3  아이템 제목       15px / 500 / 잉크
L4  본문 · 설명       14px / 400 / 잉크 또는 미드 그레이
L5  캡션 · 메타       12px / 400 / 미드 그레이   ← 라이트 그레이 ❌ (§10.2)

v1.1에서 바뀐 점: 섹션 헤더 굵기가 700 → 600입니다.

한글에서 700은 라틴보다 무겁게 렌더링됩니다. 실측 근거:

서비스 섹션 헤더
오늘의집 600 @ 16–17px
Kitchen Stories 700 @ 24px (라틴 전용 폰트)
졸리팟 v2.0 600 @ 19px

700은 가격·할인율 등 강조 전용으로만 사용합니다. 예외: 스텝 번호(§6.7) · TIP 라벨(§6.8). 버튼 글자는 600입니다(§6.1).

3.4 예외: 가격 표시

판매가: 15px / 700 / 잉크
할인율: 15px / 700 / 오렌지
정가:   14px / 400 / 미드 그레이, line-through

3.5 금지 사항

  • ❌ Pretendard를 선언만 하고 로드하지 않기
  • ❌ -webkit-font-smoothing 미지정
  • ❌ 섹션 헤더에 font-weight: 700 (600 사용)
  • ❌ L3 이하에서 700 (가격·스텝 번호·TIP 라벨 예외)
  • ❌ 자간 -0.5px 이하
  • ❌ L5 캡션에 잉크(#212121) 사용
  • ❌ 읽어야 하는 텍스트에 라이트그레이(#9E9E9E) 사용 — placeholder·비활성 전용 (§10.2)

CTA 버튼의 기본 조합인데 본문 기준(4.5:1)에 미달합니다. Kitchen Stories도 동일한 한계를 갖습니다(그들의 실측값이므로).

대응 방법
권장 화면 아래 큰 버튼은 16px 이상 / 600 이상, 콘텐츠 안 작은 버튼은 14px 이상 / 600 이상 — 버튼 텍스트는 짧아 실사용 가독성은 확보됨
엄격 준수가 필요할 때 오렌지 위에 잉크 텍스트(#212121) 사용 — 5.37 : 1 로 AA 통과
금지 오렌지 배경에 13px 이하 흰색 텍스트

② 라이트그레이 #9E9E9E / 흰색 — 2.68 : 1

AA 미달입니다. placeholder·비활성(disabled) 전용으로만 쓰세요. WCAG는 비활성 컨트롤에 명암비를 요구하지 않습니다.

용도 컬러
placeholder · 비활성 라이트그레이 #9E9E9E ✅
캡션 · 메타 · 날짜 미드그레이 #666666 (5.74:1)

v1.1에서는 캡션(L5)에 라이트그레이를 허용했으나, v2.0에서는 읽어야 하는 텍스트에 라이트그레이를 금지합니다.

10.3 보더 가시성

보더는 텍스트가 아니라 WCAG 대상은 아니지만, 1.5:1 미만이면 실기기에서 사라집니다.

조합 명암비 판정
카드 보더 #CCCFD4 / 피치크림 1.45 : 1 보임
카드 보더 / 흰색 1.56 : 1 보임
섹션 디바이더 #E5E7EB / 흰색 1.24 : 1 은은 (의도)

11. 디자인 체크리스트

컬러 - [ ] 메인 CTA가 오렌지(#FC642D)인가? — 결제하기·주문하기 포함 (딥그린 ❌) - [ ] 고른 상태(결제수단·라디오·체크박스)가 딥그린인가? - [ ] 비활성 버튼이 회색(흐린 오렌지 ❌)인가? - [ ] 링크가 파랑, 크리에이터명이 미드그레이인가? - [ ] 알림(토스트)이 잉크 바탕인가? - [ ] 확정·완료 상태가 딥그린(#145F48)인가? - [ ] 폐기된 테라코타·세이지가 남아 있지 않은가? - [ ] 노른자가 CTA로 쓰이지 않았는가? - [ ] 카드에 1px 보더(#CCCFD4)가 있는가? - [ ] 본문이 잉크(#212121)인가? (순검정 ❌) - [ ] 오렌지 면적이 7% 이내인가?

타이포그래피 - [ ] Pretendard Variable을 실제 로드했는가? - [ ] -webkit-font-smoothing: antialiased를 지정했는가? - [ ] 섹션 헤더가 19px / 600인가? (700 ❌) - [ ] 자간이 -0.3px인가? - [ ] 700이 가격 외에 쓰이지 않았는가? (스텝 번호·TIP 라벨 예외) - [ ] 카드 제목에 word-break: keep-all이 있는가?

섹션 헤더 - [ ] 제목 한 줄만 있는가? (부제 ❌) - [ ] 제목 앞 이모지가 없는가? - [ ] "전체보기" 텍스트 대신 24px 원형 화살표인가? - [ ] 제목→콘텐츠 14px, 홈 섹션 간 32px인가?

레이아웃 - [ ] 중첩 라운딩이 바깥보다 작은가? - [ ] min-height로 줄 수를 불필요하게 강제하지 않았는가?

접근성 (§10) - [ ] 캡션·메타에 라이트그레이 대신 미드그레이(#666666)를 썼는가? - [ ] 오렌지 버튼의 흰색 텍스트가 큰 버튼 16px·작은 버튼 14px 이상 / 600 이상인가? - [ ] 보더가 실기기에서 보이는가? (1.5:1 이상)

12. 이미지 규격

12.1 레시피 썸네일 — 3:4 세로

원본 자산은 3:4로 저장합니다. 숏폼(9:16)과 롱폼(16:9)을 함께 담기 위한 중간 규격입니다.

⚠ 3:4 이미지를 카드 전폭으로 넣지 마세요. 폭 330px 카드 기준 사진 높이만 440px가 되어, 카드 하나가 화면 세로를 거의 다 차지합니다.

권장: 좌측 분할 배치

사진 폭 = 카드 콘텐츠 폭의 약 42% (예: 137×183)
카드 padding 16px, 사진 border-radius 14px

13. 향후 확장

다크모드

현재 라이트모드 기준입니다. 단순 명도 반전으로는 톤이 유지되지 않으므로 별도 페어링이 필요합니다. 특히 피치크림(#FFF5EA)은 다크모드에서 대응 토큰을 새로 정의해야 합니다.

시즌 / 캠페인 컬러

별도 정의하되, 메인 CTA는 항상 오렌지로 유지해야 컨버전 데이터가 일관되게 누적됩니다.

마스코트 IP 확장

노른자 옐로우와 톤 일관성을 유지하세요.

14.2 적용 순서 (권장)

  1. CSS Variables 교체 (§8) — 대부분의 화면이 변수를 참조하므로 여기서 80% 반영됩니다
  2. Pretendard 로드 + font-smoothing 추가 (§3.1)
  3. 섹션 헤더 굵기 700 → 600 일괄 변경
  4. 하드코딩된 구 HEX 검색·치환 — 변수를 안 쓰고 직접 박아둔 값 확인 #C75D3E #8FA68E #F5F0E8 #F7F2EA #2A2A2A #6B6B6B #A8A8A8 #EDE8E0
  5. 섹션 헤더 구조 정리 (§6.6) — 부제·이모지 제거, 화살표 전환
  6. 체크리스트로 검수 (§11)

14.3 검수 시 주의

  • 가상요소(::before / ::after) 는 조상의 CSS 변수 변경을 반영하지 않는 브라우저가 있습니다. 진행 바·구분선 등에 쓰였다면 별도 확인하세요.
  • 흰 배경 위 카드는 보더 명암비를 재확인하세요(§2.6). 기존 크림 배경 기준으로 고른 보더 색은 흰 배경에서 사라집니다.
  • rgba로 틴트한 값(예: rgba(199,93,62,0.1))은 변수를 안 쓰므로 수동 교체가 필요합니다.
