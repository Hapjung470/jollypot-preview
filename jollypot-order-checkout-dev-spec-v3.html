1. 화면 구성 (위 → 아래)

#섹션구성
1주문 상품썸네일 + 상품명 + 옵션 + 금액/수량 · 헤더 우측 접기(∧), 기본 펼침
2배송지요약 카드: 수령인 + [기본] 배지 + [변경] 버튼 / 주소·연락처 1줄 / 요청사항 셀렉트
주문자 정보 섹션 없음 — 회원 정보 사용
3할인혜택[쿠폰 · 사용 가능 N장 ▾] / [쿠폰코드 입력 + 코드등록] / [적립금 N원 + 전액사용] / 사용 가능 적립금 캡션(우측 정렬)
4결제수단퀵계좌이체(히어로·기본 선택) → 신용/체크카드 → [가상계좌 ㅣ 간편결제] 2단 → "다음에도 사용" 체크박스(기본 ON)
5결제 금액총 상품 금액 / 총 배송비 / 쿠폰 할인 / 적립금 사용 → 총 결제 금액 · 하단 캡션 2줄(할인 예고 · 적립 예정)
6동의·사업자"본인은 만 14세 이상이며, 주문 내용을 확인하였습니다." + 회색 밴드(약관 링크 · 사업자 정보 접힘 · 통신판매중개 고지)
7하단 고정 바절약 스트립 + 결제하기 CTA가 한 덩어리로 고정

2. 결제수단 상세 규칙

항목규칙
선택 상태보더 #145F48 2px (라디오·체크박스도 딥그린)
버튼 높이전 수단 동일 52px · 위계는 폭으로만 표현(히어로 전폭 / 카드 전폭 / 보조 2단 하프)
퀵계좌이체기본 선택 · 카드 하단 크림 스트립 "결제할 때마다 0.5% 즉시 할인 · 횟수 무제한"
선택 시 카드 아래 크림 박스: "한 번 연결하고 무제한 혜택 받기"(13.5px/600) + "처음 한 번만 계좌를 연결하면, 다음부턴 바로 결제돼요"(12.5px 회색)
계좌 연결이 완료된 고객에게는 이 박스 미노출
가상계좌선택 시 크림 박스: "법인결제 가능" + "주문 후 발급되는 전용 계좌로 입금하면 결제가 완료돼요. 입금 기한이 지나면 주문이 자동 취소돼요."
간편결제선택 시 행 아래 전폭으로 네이버페이 라디오 펼침(검정 글씨 · 기본 선택됨)
총액 하단 캡션퀵계좌이체 선택: "퀵계좌이체 결제 시 약 N원이 즉시 할인돼요"
그 외: "퀵계좌이체로 결제하면 약 N원이 즉시 할인돼요"
N = 총 결제 금액 × 0.5%(원 단위 반올림) · 할인액을 총액에 선반영하지 않는다
적립 예정금액 행이 아니라 총액 아래 소형 회색 캡션("N P 적립 예정")

3. 하단 고정 바 · 절약 스트립

  • 절약 스트립과 CTA는 같은 고정 컨테이너에 넣어 함께 움직인다
  • 문구: "지금 주문하면 N원을 아껴요" · N = 확정 할인 합계(쿠폰 + 적립금 사용). 퀵계좌 예상 할인은 합산하지 않는다
  • N = 0이면 스트립 미노출 · 이때만 바 상단에 1px 구분선(#E5E7EB) 노출. 스트립이 있으면 구분선 없음(크림 면이 경계 전담)

4. 레이아웃·타이포

  • 섹션 헤더 17px/600 · 여백 상 16 / 하 10 · 입력·선택 행 높이 44~48px · 금액 행 간격 5px
  • 섹션 구분 = 1px 헤어라인 #E5E7EB 좌우 풀블리드 · 음수 마진 사용 시 부모 패딩과 반드시 상쇄되게(그렇지 않으면 화면 밖으로 넘침)
  • 할인혜택 라벨·값 전부 #666666 일반체(볼드 금지) · 사업자 정보 영역도 볼드 없음
  • 오렌지 #FC642D는 CTA + 혜택 숫자 + 할인 금액에만 · 크림 배경 위 오렌지 본문 금지(명암비 미달)
  • Pretendard Variable 로드 + -webkit-font-smoothing:antialiased + 자간 -0.3px + word-break:keep-all
  • 섹션 제목 표기: "할인혜택"·"결제수단"은 붙여쓰기

5. 분기·조건부 렌더링

조건동작
배송지 미등록(신규)요약 카드 대신 주소 입력 폼 노출 · 등록 후에는 요약 카드로 전환
[변경] 탭배송지 목록/입력은 별도 시트로 분리 — 주문 화면에 폼을 펼치지 않는다
퀵계좌 연결 완료"한 번 연결하고 무제한 혜택 받기" 박스 미노출
확정 할인 0원절약 스트립 미노출 + 하단 바 상단 구분선 노출
쿠폰/적립금 0행은 유지하되 값만 "사용 가능 0장" / "0원"

6. 결제 실패·중단 상태 (5종)

원칙: 실패 화면이 답해야 할 것은 "왜 실패했나"가 아니라 ①내 돈이 나갔나 ②이제 뭘 하면 되나 두 가지다. 청구 여부가 확실한 상태에는 "결제 금액은 청구되지 않았어요" 확인 배지를 반드시 넣고, 다음 행동을 1순위 버튼으로 배치한다.

#상태형태구성·규칙
1수단 거절
(한도·잔액·카드정지)		바텀시트제목 "결제가 완료되지 않았어요" · 청구 안내 배지 노출
1순위: 퀵계좌이체 대안 카드(딥그린 2px 보더 · "0.5% 즉시 할인" 표기) · 2순위 [다른 카드로 다시 시도] · 3순위 텍스트 [주문서로 돌아가기]
주문번호·오류코드는 접힘 안에만(기본 닫힘), 화면에 코드 노출 금지
단, 이미 퀵계좌이체로 실패한 경우 대안 카드를 다른 수단으로 교체
2결제 중단
(사용자 취소·앱 미복귀)		바텀시트제목 "결제를 취소했어요" · 에러 컬러·청구 배지 사용 금지(실패가 아님, 중립 아이콘)
본문 "주문 내용은 그대로 있어요" · 1버튼 [이어서 결제하기]
3결과 확인 중
(타임아웃·응답 없음)		전체 화면스피너 + "결제 결과를 확인하고 있어요"
실패로 단정 금지 · 청구 배지 넣지 않는다(청구 여부 불확실)
재시도 버튼 제공 금지 + 크림 박스에 "중복 결제를 막기 위해 다시 결제하지 말아주세요" 명시
단일 버튼 [주문 내역에서 확인하기] · 화면을 닫아도 서버가 결과 확정
4결제 중 품절전체 화면품절 상품을 썸네일+품절 오버레이로 명시 · 청구 배지 노출
재시도 버튼 없음(재시도가 무의미) · [재입고 알림 받기] / [장바구니로 돌아가기]
다품목 주문이면 [품절 상품 빼고 주문하기]를 1순위로
5시스템·네트워크 오류바텀시트"잠시 문제가 생겼어요" + 청구 배지 · [다시 시도하기] 1순위 · [고객센터 문의하기] 텍스트 보조
  • 시트 vs 전체 화면 분기: 같은 주문으로 복구 가능하면 바텀시트(주문 컨텍스트 유지 = 재시도 마찰 최소), 주문 상태 자체가 바뀌었으면 전체 화면(3·4번)
  • 시트 표시 중 배경 스크롤 잠금 · 딤(rgba(0,0,0,.45)) 탭 시 닫힘(단, 3번은 닫힘 불가)
  • PG 응답코드 → 5개 상태 매핑표 필요 · 미분류 코드는 5번(시스템 오류)으로 폴백
  • 3번은 결과 폴링 + 서버 웹훅 병행 · 사용자가 이탈해도 서버가 결과를 확정하고 알림 발송 · 동일 주문 재결제 요청 차단(멱등키) 필수

7. 착수 전 확정 필요

① 수단별 선택률 추적 이벤트 · 실패 상태별 발생률 추적(상태 5종 각각)
② PG 응답코드 → 상태 5종 매핑표(PG 문서 확보 후 확정)
③ 배송비 첫 노출 시점 — 결제 단계에서 처음 보이면 이탈 요인. 상품 카드 또는 장바구니 단계 노출 권장
④ 현금영수증 신청 UI(가상계좌 선택 시) — 이번 프로토 미포함, 개발 범위 판단 필요
⑤ 적립 예정 P 산식(적립 정책 확정 후 연결)
