AI가 태그를 붙일 때 지키는 규칙

태그 사전 v1이 「무엇을 붙이나」를 정했다면, 이 문서는 「어떻게 붙이나」를 정합니다. 규칙마다 레시피 158건에서 실제로 틀린 사례를 근거로 붙였습니다.

원칙 5개 판정 규칙 6칸 함정 10개 실측 프롬프트 초안 포함 2026-09-10

01태그는 무엇을 하려고 붙이나

이걸 먼저 정해야 「좋은 태그」를 판단할 수 있습니다. 태그는 예쁘게 붙이는 게 아니라 셋 중 하나를 하려고 붙입니다.

쓰임 1

밖에서 사람을 데려온다

「두부조림」을 찾는 월 80,740명에게 우리 페이지가 걸립니다. 태그 이름이 곧 페이지 제목이 되므로, 태그는 사람들이 실제로 치는 말이어야 합니다.

쓰임 2

안에서 다음 레시피로 넘긴다

두부조림을 본 사람에게 다른 두부 요리를 보여줍니다. 이때 필요한 건 정확한 분류지 많은 태그가 아닙니다.

쓰임 3

냉장고와 맞춰본다

보관 중인 재료로 만들 수 있는 레시피를 찾습니다. 이름이 통일돼 있지 않으면 냉장고의 「계란」이 레시피의 「달걀」을 못 찾습니다.

쓰임이 아닌 것

많이 붙이는 것

태그 수는 성과가 아닙니다. 158건 중 99건에 붙는 「간단요리」는 아무것도 구분해주지 못합니다. 모두에게 붙는 태그는 없는 것과 같습니다.

그래서 판단 기준은 하나입니다. 이 태그를 붙였을 때 ①검색에서 걸리거나 ②다음 레시피로 넘겨주거나 ③냉장고에서 찾아지거나 셋 중 하나가 되는가. 아니면 붙이지 않습니다.

02원칙 다섯 개

아래 모든 규칙이 이 다섯에서 나옵니다. 판단이 갈릴 때는 여기로 돌아옵니다.

  1. 사전에 있는 말만 붙인다 AI는 새 태그를 만들 수 없습니다. 사전이 곧 쓸 수 있는 말의 전부입니다. 자유롭게 붙이면 「존맛」·「우리집레시피」·「두부요리」가 뒤섞여 한 달이면 못 씁니다.
  2. 없는 말은 버리지 말고 쌓는다 사전에 없다고 무시하면 사전이 영영 안 자랍니다. 못 붙인 말은 후보함에 기록합니다. 같은 말이 3건 모이면 사람이 판단합니다.
  3. 확실하지 않으면 비운다 빈 칸은 나중에 채울 수 있지만, 잘못 붙은 태그는 사용자가 먼저 발견합니다. 「바나나구이」 같은 태그가 한 번 보이면 신뢰를 잃습니다.
  4. 어디서 봤는지 함께 적는다 태그마다 근거 위치를 남깁니다 — 제목에서 봤나, 재료란에서 봤나, 조리 순서에서 짐작했나. 이게 검수의 기준이 됩니다(05번).
  5. 지우지 말고 넘겨보낸다 태그를 합치거나 이름을 바꿔도 옛 이름을 지우지 않습니다. 사전에 「옛 이름 → 새 이름」을 남기고, 옛 주소로 들어오면 새 페이지로 보냅니다.

주는 것

항목필드쓰임158건 보유
제목title가장 중요합니다. 대표 재료·방법·종류·원작자가 대부분 여기 있습니다158
재료 목록ingredients[].name재료 칸의 원천. 이름 통일 대상158
조리 순서steps[].description방법 칸 판정. 마지막 두 단계만 봅니다158

조리 시간durationSeconds태그 아님 — 필터로 처리158

여기에 태그 사전 전체를 함께 줍니다. 사전 없이 태그를 요청하면 규칙 1이 깨집니다.

받는 것

칸마다 값과 근거를 짝으로 받습니다. 근거가 이 설계의 핵심입니다.

{
  "ingredients": [
    { "tag": "두부", "from": "title" },
    { "tag": "대파", "from": "ingredients" }
  ],
  "mainIngredient": { "tag": "두부", "from": "title" },
  "method":  { "tag": "조림", "from": "title" },
  "kind":    { "tag": "밑반찬", "from": "title" },
  "situation": [{ "tag": "저녁", "from": "title" }],
  "eater":   null,
  "author":  null,
  "candidates": [
    { "word": "유부", "where": "ingredients", "why": "재료란에 있으나 사전에 없음" }
  ]
}

from은 title · ingredients · steps 셋 중 하나. 어디서도 못 찾으면 그 칸은 null.

확신도를 숫자로 받지 않는 이유. 「0.82」 같은 점수는 사람이 검증할 수 없습니다. 반면 「제목에서 봤다」는 열어서 바로 확인됩니다. 그리고 근거 위치가 곧 정확도입니다 — 제목에서 온 태그는 거의 맞고, 조리 순서에서 짐작한 태그가 틀립니다.

그래서 검수 큐를 이렇게 만듭니다. 「근거가 조리 순서인 것만 보기」. 158건에 붙여보니 방법 칸에서 제목 근거는 거의 정확했고, 조리 순서 근거에서 오류가 몰렸습니다.

04칸별로 정하는 순서

각 칸마다 위에서부터 내려가며 먼저 걸리는 것으로 끝냅니다. 아래까지 내려가도 안 걸리면 비웁니다.

재료

  1. 재료란을 한 줄씩 사전에 맞춥니다「다진마늘」 → 마늘. 이름 통일표를 씁니다.
  2. 양념층은 건너뜁니다소금·간장·설탕·식용유 등 약 40종. 158건 중 소금이 49건에 있습니다.
  3. 한 칸에 여러 재료가 들어있으면 나눕니다실제 사례: "고춧가루, 후추, 오레가노, 마늘가루"가 재료 한 칸에 들어와 있습니다. 쉼표로 나눠 각각 판정합니다.
  4. 사전에 없으면 후보함으로「유부」·「명란」·「샤인머스캣」은 지금 사전에 없습니다. 버리지 않고 기록합니다.

대표 재료 정하기

  1. 제목에 있는 재료가 대표입니다실측 근거: 제목 등장률이 떡·가지·순두부 100%, 두부·애호박 62%인 반면 계란 11%·양파 3%입니다. 제목이 주인공을 가려줍니다.
  2. 제목에 재료가 없으면 재료란 첫 항목단, 첫 항목이 양념이면 다음으로 넘어갑니다. 실제 오류: 「고깃집 스타일 된장찌개」의 대표가 양파로 잡혔습니다.
  3. 주인공이 사전에 없으면 비웁니다실제 오류: 「감바스」의 대표가 마늘, 「유부된장국」의 대표가 대파로 잡혔습니다. 새우·유부가 없거나 사전에 없어서 엉뚱한 게 올라온 것입니다. 이럴 땐 비우고 후보함에 넣습니다.

방법

  1. 제목에 방법이 있으면 그것으로 끝「애호박볶음」이면 볶음. 더 볼 것 없습니다.
  2. 종류가 디저트·빵·면이면 방법을 비웁니다케이크도 굽고 베이글도 굽습니다. 하지만 「구이」가 아닙니다. 158건 중 12건이 이 함정에 걸렸습니다.
  3. 제목에 없으면 마지막 두 단계만 봅니다실측: 방법 동사가 조리 순서 앞뒤 모두에 나오는 레시피가 47건입니다. 전체를 보면 볶음·구이·국물이 한꺼번에 잡힙니다. 마지막이 결론입니다.
  4. 하나만 고릅니다둘 이상 걸리면 조림 → 무침 → 볶음 → 찜 → 튀김 → 전 → 국물 → 구이 순으로 앞선 것을 씁니다. 구이가 가장 뒤인 이유는 「굽다」가 가장 흔해서입니다.

종류

  1. 제목의 마지막 명사가 대개 종류입니다「스테이크 샌드위치」는 샌드위치이지 스테이크가 아닙니다. 「짜장 떡볶이」는 떡볶이입니다.
  2. 하나만 고릅니다158건에서 둘 이상 붙은 게 16건이었고 대부분 하나가 틀렸습니다.
  3. 낱말 안에 숨은 글자를 조심합니다05번 함정표를 반드시 확인합니다.

상황 · 누가 먹나 · 누구 레시피

  • 상황은 제목에 드러난 것만 붙입니다. 조리 시간이 짧다고 「간단요리」를 붙이지 않습니다 — 이 태그는 사전에서 뺐습니다.
  • 누가 먹나는 제목이나 설명에 명시된 경우만. 「아기」·「이유식」·「아이」라는 말이 실제로 있어야 합니다. 없으면 온가족이고 태그를 붙이지 않습니다. 재료로 추측하지 않습니다 — 순한 맛이라고 아기용이 아닙니다.
  • 누구 레시피는 제목에 사람 이름이나 프로그램 이름이 있을 때만. 채널명은 근거가 아닙니다 — 158건에서 유명인 레시피 3건 중 2건이 채널명 ≠ 원작자였습니다.

06비우는 기준과 후보함

비워야 할 때

  • 제목·재료란 어디에도 근거가 없고 조리 순서에서 짐작만 되는 경우
  • 같은 칸에 둘 이상이 비슷하게 걸리는 경우 (하나를 못 고르겠으면 비웁니다)
  • 주인공 재료가 사전에 없는 경우 (대표 재료만 비우고, 나머지 재료 태그는 붙입니다)
  • 함정표의 낱말에 걸렸는데 진짜인지 판단이 안 서는 경우

158건 실측 기준으로 방법 43% · 종류 37%가 비어 있습니다. 이게 실패가 아니라 정상입니다. 억지로 채운 결과가 「바나나구이」였습니다.

후보함이 알림을 보내는 조건

같은 말이 3건 모이면 운영자 화면에 뜹니다. 그때 사람이 셋 중 하나를 고릅니다.

판단언제예시
사전에 넣기검색량이 있고 앞으로도 나올 재료·음식유부 · 명란 · 마라탕
기존 태그로 묶기이미 있는 태그의 다른 이름「달걀」 → 계란 · 「간마늘」 → 마늘
버리기번역 오류 · 일회성 · 태그로 쓸모없음「그린 반죽」 · 「풀비버」 · 「흰색 랩 재료」

후보함이 없으면 사전이 안 자랍니다. 통제어휘만 두면 새 재료·새 음식이 영영 안 들어옵니다. 후보함은 목록에 없는 말을 사고가 아니라 신호로 바꾸는 장치입니다.

07사람이 하는 일

전수 검수는 처음 한 번만 하고, 그다음은 걸러서 봅니다.

단계무엇을얼마나
첫 백필기존 158건 일괄 태깅 후 전수 검수1회 · 이 결과로 정확도를 잽니다
상시 검수근거가 조리 순서인 태그만추정 전체의 2~3할
후보함3건 모인 말 판단주 1회
신규 노출3건이 차서 열린 태그 확인알림이 오면

검수할 때 보는 것

  • 대표 재료가 제목의 주인공과 같은가
  • 방법이 완성 방식인가, 중간 과정인가
  • 종류가 하나인가
  • 「누가 먹나」가 본문에 근거가 있나 (추측이 아닌가)
  • 함정표 낱말이 진짜인가

첫 백필 검수가 정확도 기준을 만듭니다. 158건을 사람이 전부 보면 칸별 정확도가 나옵니다. 그 숫자로 「어디까지 자동으로 두고 어디부터 검수할지」를 정합니다. 지금 미리 정하지 않습니다.

08프롬프트 초안

위 규칙을 그대로 옮긴 것입니다. 사전은 별도로 함께 전달합니다.

당신은 요리 레시피에 분류 태그를 붙입니다.
아래 사전에 있는 말만 쓸 수 있습니다. 새 태그를 만들지 마세요.

[사전]
재료: (60개 목록 + 이름 통일표)
양념(태그 붙이지 않음): (약 40종)
방법: 볶음 조림 무침 찜 구이 튀김 전 국물
종류: (28개 목록)
상황: (12개 목록)
누가 먹나: 아기 아이 이유식
누구 레시피: (인물·프로그램 목록)

[가장 중요한 규칙]
1. 확실하지 않으면 비웁니다. 빈 칸은 괜찮지만 틀린 태그는 안 됩니다.
2. 태그마다 어디서 봤는지 적습니다: title / ingredients / steps
3. 사전에 없는 말은 candidates에 기록합니다. 버리지 마세요.

[재료]
- 재료란을 한 줄씩 보고 사전 이름으로 바꿉니다 (다진마늘 → 마늘)
- 양념 목록에 있는 것은 건너뜁니다
- 한 칸에 쉼표로 여러 개가 있으면 나눠서 봅니다
- "A 또는 B"는 앞의 것만 씁니다

[대표 재료 — 하나만]
- 제목에 나오는 재료가 대표입니다
- 제목에 재료가 없으면 재료란 첫 항목 (단 양념은 제외)
- 제목의 주인공이 사전에 없으면 비우고 candidates에 넣습니다

[방법 — 하나만]
- 제목에 방법이 있으면 그것으로 끝냅니다
- 종류가 디저트·샌드위치·만두·면요리이면 방법을 비웁니다
  (케이크도 굽고 베이글도 굽지만 구이가 아닙니다)
- 제목에 없으면 조리 순서의 마지막 두 단계만 봅니다
  (중간에 볶는다고 볶음이 아닙니다. 마지막이 결론입니다)
- 둘 이상 걸리면 이 순서로: 조림 무침 볶음 찜 튀김 전 국물 구이

[종류 — 하나만]
- 제목의 마지막 명사가 대개 종류입니다
  "스테이크 샌드위치" → 샌드위치, "짜장 떡볶이" → 떡볶이

[함정 — 글자만 맞추면 틀립니다]
낱말 안에 숨은 글자에 속지 마세요. 낱말 단위로 보세요.
  밥   → 덮밥·비빔밥·볶음밥·유부초밥의 밥은 재료가 아닙니다
  국   → 한국·중국식·콩국수·비빔국수의 국은 국물이 아닙니다
  파   → 파스타·파프리카·파슬리·파인애플의 파는 대파가 아닙니다
  떡   → 떡볶이·떡국은 종류이지 재료 떡이 아닙니다
  김   → 김치·김밥의 김은 재료 김이 아닙니다
  차   → 27일차·차돌박이의 차는 음료가 아닙니다
  죽   → 반죽의 죽은 죽이 아닙니다
  가지 → "3가지 재료"의 가지는 채소가 아닙니다
  무   → 무침의 무는 채소가 아닙니다
판단이 안 서면 비우세요.

[누가 먹나]
- 제목이나 설명에 "아기·아이·이유식"이라는 말이 실제로 있을 때만
- 재료가 순하다고 아기용으로 짐작하지 마세요
- 없으면 null (기본값은 온가족이며 태그를 붙이지 않습니다)

[누구 레시피]
- 제목에 사람 이름이나 프로그램 이름이 있을 때만
- 채널 이름은 근거가 아닙니다 (올린 사람과 원작자가 다를 수 있습니다)

[출력]
JSON만 출력합니다. 설명을 붙이지 마세요.
{
  "ingredients": [{"tag":"", "from":""}],
  "mainIngredient": {"tag":"", "from":""} 또는 null,
  "method": {"tag":"", "from":""} 또는 null,
  "kind": {"tag":"", "from":""} 또는 null,
  "situation": [{"tag":"", "from":""}],
  "eater": {"tag":"", "from":""} 또는 null,
  "author": {"tag":"", "from":""} 또는 null,
  "candidates": [{"word":"", "where":"", "why":""}]
}

사전을 프롬프트에 매번 넣습니다. 사전이 바뀌면 프롬프트도 자동으로 따라가야 하므로, 사전은 코드에 박지 말고 어드민 테이블에서 읽어와 조립합니다. 사전이 늘어나도 프롬프트를 손대지 않습니다.

09사전을 바꿀 때

사전은 반드시 바뀝니다. 바뀔 때 페이지가 죽지 않게 하는 규칙입니다.

바꾸는 일해야 하는 것예시
태그 추가추가만 하면 됩니다. 3건이 차면 저절로 열립니다「유부」 신설
이름 바꾸기옛 이름을 넘겨보내기 표에 남깁니다「유아식」 → 「아기」
두 태그 합치기합쳐지는 쪽을 넘겨보내기 표에 남기고, 붙어 있던 레시피를 옮깁니다「아이반찬」 + 「아기반찬」
태그 삭제하지 않습니다. 숨김으로 두고 넘겨보냅니다—

태그 이름이 곧 페이지 주소입니다. 지우면 그 주소로 들어오던 사람이 빈 화면을 봅니다. 검색엔진에 올라가 있으면 더 오래 갑니다.

사전에 새 태그를 넣는 조건

  1. 후보함에 3건 이상 쌓였다사람이 임의로 추가하지 않습니다. 콘텐츠가 신호를 줄 때만.
  2. 검색량을 확인했다사람들이 쓰는 말인지 봅니다. 실측 방법은 태그 사전 v1 문서에 있습니다.
  3. 기존 태그와 겹치지 않는다겹치면 신설이 아니라 이름 통일표에 넣습니다. 「간마늘」은 새 태그가 아니라 마늘입니다.

10내보내기 전 점검

태그 한 건을 화면에 내보내기 전에 확인하는 목록입니다.

확인기준
사전에 있는 말인가없으면 후보함으로
레시피가 3건 이상인가미만이면 어드민에서만 보임
대표 재료가 제목의 주인공인가아니면 비움
방법이 완성 방식인가중간 과정이면 비움
종류가 하나인가둘이면 하나를 고르거나 비움
함정표 낱말에 걸렸는가걸렸으면 낱말 단위로 다시 봄
「누가 먹나」에 본문 근거가 있는가추측이면 비움
원작자를 채널명으로 판단하지 않았는가제목 근거만 인정
