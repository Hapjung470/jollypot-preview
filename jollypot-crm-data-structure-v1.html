졸리팟 CRM 고도화
회원 정보가 샵바이에 있는 게 제약인가

2026.11.02 · 샵바이 회원 API로 회원 수 직접 집계(개인정보는 꺼내지 않고 숫자만) · 샵바이 웹훅·서버 API 명세 확인
결론 3줄
  1. 개인정보가 샵바이에 있는 것 자체는 제약이 아닙니다. 이메일·전화·수신 동의는 서버 API로 한 번에 1만 명씩 읽을 수 있습니다. 회원가입·정보 변경·주문·장바구니·탈퇴는 웹훅(사건이 생기면 바로 알려 주는 기능)으로 받습니다. 오늘 실제로 API로 회원 50.8만 명을 셌습니다.
  2. 진짜 제약은 넷입니다. ① 레시피 행동 데이터가 샵바이에 없음 ② 광고 수신 동의 ③ 행동에 맞춰 자동으로 보내는 엔진이 없음 ④ 개인정보를 밖으로 옮길 때의 법·보안 부담.
  3. 추천 구조는 「연락처는 샵바이에 두고, 회원번호로만 움직이기」입니다. 사람을 고르는 계산은 회원번호로 하고, 보내는 건 샵바이 메시지나 앱 푸시로 합니다. 이러면 개인정보를 밖으로 꺼낼 일이 거의 없습니다.

세 가지가 보입니다.

  • 회원 70%는 1년 넘게 로그인하지 않았습니다. 대부분 2024년 8월에 옮겨 온 하봄몰 회원입니다.
  • 최근 1년 가입자의 동의율(42%)이 이전(99%)보다 크게 낮습니다. 가입 화면에서 동의 칸 기본값이 바뀐 것으로 보입니다. 지금 42%가 실제 동의에 가까운 값이고, 이전 99%는 기본 체크였을 수 있습니다. 확인이 필요합니다.
  • 광고를 실제로 보낼 수 있는 활동 회원은 약 9.3만 명입니다. 모든 CRM 계획의 상한입니다. 앱 푸시 동의는 마이앱 안에만 있었으므로, 새 앱에서 0부터 다시 받습니다.
먼저 확인할 법적 의무 하나. 광고 수신 동의는 받은 날부터 2년마다 동의 여부를 다시 확인해야 합니다(정보통신망법 제50조 제8항·시행령 제62조의3, 어기면 과태료 3천만 원 이하). 하봄몰 이관 회원 33.8만 명의 동의일이 2024년 8월로 기록돼 있다면, 2026년 8월에 이미 알림 기한이 지났습니다. 샵바이의 「수신 동의 확인 자동 안내」가 켜져 있었는지 운영 설정에서 확인해야 합니다. 원래 하봄몰 시절 동의일이 따로 남아 있다면 기한은 더 이릅니다.

2. 샵바이가 내주는 것 — 제약이 아닌 이유

필요한 것샵바이 제공 방법확인
이메일·전화·이름·생일·성별회원 목록 API (한 번에 최대 1만 명, 가입일·수정일·마지막 로그인으로 걸러 읽기)오늘 실행
SMS·이메일·앱 푸시 수신 동의같은 API의 isSmsAgreed·isDirectMailAgreed·isPushNotificationAgreed오늘 실행
실시간 사건웹훅: 회원가입·회원정보 변경(동의 변경 포함)·등급·그룹 변경·휴면·탈퇴·주문 생성·주문 상태 변경·장바구니 담기·적립금 지급·상품 후기명세 확인
구매 이력주문 API (37,109건 시간대 분석 때 이미 사용)사용 중
나눈 집단을 샵바이에 돌려 넣기회원 그룹 만들기·회원을 그룹에 넣기 API → 그룹 대상 쿠폰명세 확인
보내기샵바이 메시지(SMS·알림톡·브랜드 메시지): 엑셀 대상·예약·반복 발송 (9/29 업데이트)공지 확인

샵바이 쪽 작은 제약 (오늘 겪은 것)

  • 회원 검색은 가입 기간을 꼭 넣어야 하고, 너무 넓으면 거절합니다. 1년 단위로 나눠야 했습니다. 마지막 로그인 검색은 1년 범위까지만 됩니다.
  • 웹훅은 실패해도 다시 보내 주지 않습니다. 「실패한 웹훅 조회」 API로 매일 한 번 빠진 것을 맞춰야 합니다.
  • 앱 푸시 발송은 마이앱 상점에만 있습니다. 새 앱으로 바꾸면 푸시는 우리가 따로 붙여야 합니다(OneSignal 견적 트랙).

이 정도는 개발로 넘을 수 있는 수준입니다.

3. 진짜 제약 4가지

제약무슨 뜻인가대응
① 레시피 행동이 샵바이에 없음샵바이는 장바구니·주문·후기만 압니다. 「김치찜 레시피를 저장했다」「요리 후기를 썼다」는 졸리팟 DB에만 있습니다. 졸리팟 CRM의 핵심인 「레시피 → 장보기」 연결이 바로 이 데이터입니다.졸리팟 서버가 행동 기록을 회원번호와 함께 남기게 합니다. 이벤트 이름은 처음부터 정해 둡니다.
② 로그인 전 방문자인스타에서 들어와 레시피만 보고 나간 사람은 누구인지 모릅니다.로그인 순간 「이 기기 = 회원번호」로 이어 붙입니다. 앱은 설치 기기 ID와 회원번호를 묶습니다.
③ 수신 동의활동 회원 중 보낼 수 있는 사람이 9.3만 명이고, 최근 가입자는 42%만 동의했습니다. 새 앱 푸시는 0부터 시작합니다.동의를 늘리는 장치가 CRM 1순위입니다. 「재입고·오픈 알림 받기」「적립금 소멸 알림」처럼 받을 이유를 줍니다.
④ 자동 발송 엔진이 없음샵바이 메시지는 사람이 엑셀로 대상을 올리고 예약하는 방식입니다. 「레시피 저장 후 다음 날 저녁 준비물 딜 알림」처럼 사람마다 다른 순간에 맞춰 보내지는 못합니다.처음엔 하루 1번 배치(전날 저장한 사람 → 그룹 → 예약 발송)로 반자동화합니다. 물량이 커지면 CRM 도구를 붙입니다.

앱 푸시는 처음부터 회원번호로 붙입니다. 푸시 도구는 「외부 ID = 회원번호」만 알면 되고, 전화·이메일이 필요 없습니다. 광고 푸시 동의는 샵바이 회원 정보의 「푸시 알림 동의」 칸에 기록해서, 원본을 한 곳에 둡니다.

5. 졸리팟 첫 CRM 시나리오 5개

#누구에게무엇을데이터성격
1어제 레시피를 저장했는데 그 재료 딜을 안 산 사람오늘 저녁 4시, 그 레시피 준비물 딜졸리팟 저장 + 샵바이 주문광고 동의자만
2재입고·오픈 알림 신청자열리는 순간 알림샵바이 재입고 신청신청한 정보
3첫 구매 7일 뒤「해 보셨어요?」 사진 후기 요청 + 적립금 안내샵바이 주문 웹훅후기 요청은 성격 판단 필요
4적립금·쿠폰 소멸 7일 전소멸 안내샵바이 적립금광고 (KISA 2025-12 해석)
511개월째 로그인 없는 회원휴면 전 안내 + 이번 주 식단샵바이 마지막 로그인휴면 안내는 정보성, 식단은 광고

1번이 졸리팟만 할 수 있는 시나리오입니다. 레시피 행동과 구매가 같은 회원번호로 이어져 있어야 가능하고, 이 문서의 구조가 그 전제를 만듭니다.

6. 개발사에 줄 요구사항

  1. 행동 기록: 레시피 보기·저장·요리 후기·장보기 담기를 회원번호와 시각으로 남기는 표 하나. 이름은 미리 정합니다(recipe_view·recipe_save·cook_review·cart_from_recipe).
  2. 샵바이 웹훅 받기: 회원가입·회원정보 변경·탈퇴·주문 생성·주문 상태 변경·장바구니. 매일 「실패한 웹훅 조회」로 맞추기.
  3. 개인정보 복사 금지: 졸리팟 DB에는 회원번호만 둡니다. 이메일·전화는 저장하지 않습니다.
  4. 앱 푸시: 푸시 도구의 외부 ID = 샵바이 회원번호. 광고 푸시 동의는 샵바이 「푸시 알림 동의」 칸에 씁니다.
  5. 로그인 이어 붙이기: 웹·앱 모두 로그인 때 기기 ID와 회원번호를 연결합니다. GA4의 사용자 ID에는 회원번호를 넣습니다. 이메일·전화는 넣지 않습니다.

7. 정해 주실 것

  1. 2년 재확인 의무: 샵바이 운영 설정에서 「수신 동의 확인 안내」가 켜져 있는지 확인. 꺼져 있었다면 바로 발송이 필요합니다.
  2. 최근 가입자 동의율 42%: 가입 화면 동의 칸을 바꿀지. 기본 체크는 무효라 그대로 둡니다. 대신 「재입고·오픈 알림 받기」처럼 받을 이유를 붙여 올리는 방향을 권합니다.
  3. 보내는 방법: 지금은 A(개인정보를 꺼내지 않는 방식)로 시작하고, 1번 시나리오부터 해 볼지.
