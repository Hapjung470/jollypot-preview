v10 — 필수옵션 1개 케이스 추가 (2026-08-20)

케이스 목록에 필수 1개가 빠져 있었다. 색상만, 사이즈만 있는 상품이 실무에서 가장 흔한 형태인데 필수 2·3·2+선택1만 있었다.

동작: 셀렉트 하나만 렌더링되고 고르는 즉시 완료 상태로 전환된다(순서 강제 대상이 없음). 배지는 개수와 무관하게 항상 표기한다 — 필수가 하나뿐이어도 "이건 반드시 골라야 한다"는 신호는 동일하게 필요하다.

기본 진입 케이스도 필수 1로 바꿨다. 가장 단순한 형태부터 보는 것이 검토 순서로 자연스럽다.

v9 — 배지가 커다란 블록으로 렌더링되던 문제 (2026-08-19)

증상: "선택" 배지만 크림색 큰 사각형으로 나와 사진 자리처럼 보였다. "필수" 배지는 정상.

원인 — CSS 클래스 이름 충돌. 배지 마크업이 class="opt-badge opt"였는데, .opt는 옵션 목록의 각 행에 쓰는 클래스이기도 하다.

.opt { padding:14px 15px; display:flex; min-height:54px; }
→ 배지가 이 규칙을 함께 물려받아 최소 높이 54px · 패딩 14px짜리 블록이 됐다. "필수" 배지는 .req 규칙이 존재하지 않아 영향을 받지 않았고, 그래서 둘만 크기가 달랐다.

조치: 수식어 클래스를 .badge-req / .badge-opt로 네임스페이스화하고, 배지에 align-self:center · white-space:nowrap을 명시해 부모 flex의 영향에서 분리했다.

개발 규칙: 수식어(modifier) 클래스는 반드시 블록 이름을 접두어로 붙인다. .opt · .on · .sub처럼 짧고 일반적인 이름을 수식어로 쓰면 다른 컴포넌트의 규칙을 조용히 물려받아 에러 없이 화면만 깨진다.

v8 — 추가상품 썸네일 제거 (2026-08-19)

시트 안에서 이미지를 가진 요소가 추가상품 하나뿐이라 시각 리듬이 깨지고 있었다. 옵션 행·텍스트 입력·선택 결과 카드가 전부 텍스트 기반인데 추가상품만 썸네일을 갖고 있었다.

제거 후 구조: [✓] 상품명 ......... 가격 — 체크박스를 앞으로 빼서 "고르는 것"임을 즉시 알리고, 가격은 우측 정렬로 세로로 비교되게 했다. 옵션 행의 이름 …… +N원과 같은 문법이 된다.

부수 이득: 추가상품은 파트너가 등록하는 별도 상품이라 대표 이미지가 없거나 품질이 들쭉날쭉할 수 있다. 이미지를 안 쓰면 그 의존이 사라지고 깨진 썸네일이 뜰 위험도 없다.

다시 넣어야 할 때: 추가상품이 실제로 운영되고 클릭률이 낮게 나오면 이미지를 재검토한다. 현재 졸리팟 몰의 추가상품 보유는 0건이라 판단 근거가 없다.

구매 플로우 v10 — 옵션 경우의 수 전체 대응 (2026-08-19)

샵바이 실측(shopby-option-vs-addproduct-v1.md) 기준으로 10가지 케이스를 상단 토글로 전부 확인할 수 있습니다. [텍스트 선택만]은 시트가 열리되 아무것도 강제하지 않는 유일한 케이스(즉시 구매 가능 · 입력하면 유효해야 함)로, QA에서 놓치기 쉬운 경로입니다. [추가상품(케미콩)]은 실사용 상품(케미콩 이지컷 네임테이프 — 샵바이 추가상품 기능 첫 사용)을 반영한 케이스로, 추가상품이 자체 옵션과 수량을 갖는 구조까지 다룹니다. 추가상품 옵션은 칩이 아니라 본품과 같은 셀렉트-목록(아래 펼침)으로 처리합니다 — 옵션명은 파트너 입력값이라 길이를 통제할 수 없고, 체크 시 목록이 자동으로 펼쳐집니다. 레이아웃(2026-09-01 실측 개선): 단가는 상품명 줄 오른쪽 · 옵션 셀렉트와 수량은 아래 전폭 · 합계는 수량 줄 오른쪽 — 실측 옵션명("마음을 전하는 테이프(이지컷)_생일축하해 +900원")이 우측 가격 컬럼에 눌리면 두 줄로 꺾이기 때문입니다(샵바이 기본 스킨의 실패 재현 방지).
용어 정리(2026-09-01): 추가구성/추가구성상품/추가상품은 전부 같은 개념(샵바이 additionalProducts)입니다. 공식 용어 "추가상품"으로 통일하며, 형태가 두 가지입니다 — 단일형(옵션 없음, 체크만 · [추가상품·단일] 케이스) / 옵션형(자체 옵션 보유, 셀렉트로 선택 · [추가상품·옵션형] 케이스). 소비자 화면 헤더는 "함께 사면 좋아요"를 유지합니다. 디자인·옵션 세부 구성은 어드민 실값 기준으로 확정하세요. 화면은 전부 옵션 데이터로부터 렌더링되며, 케이스별 하드코딩이 없습니다.

2. ★ 가장 중요한 설계 판단 — 선택옵션은 "+N원"이 아니라 절대가로 표기한다

샵바이에서 선택옵션 가격 = 본품가 + addPrice이고, addPrice에 음수가 들어갑니다. 실측 사례(캡슐 네임 스탬프 #134224312): 본품 6,700원, 선택옵션 리필잉크 addPrice −4,200 → 실제 판매가 2,500원.

이걸 필수옵션처럼 증분 표기하면 "+ −4,200원"이라는 말이 안 되는 화면이 나옵니다. 그래서 필수옵션은 증분(+8,500원), 선택옵션은 절대가(2,500원)로 표기 규칙을 나눴습니다.

부수 위험도 명시: 선택옵션 가격이 본품가에 종속되므로 본품 할인·쿠폰이 바뀌면 부가품 가격이 같이 흔들립니다. 가격이 자주 바뀌는 부가품은 선택옵션이 아니라 추가상품으로 등록해야 합니다.

4. 공통 규칙

· 선택 완료 상태(2026-09-01 개선): 배지 필수/선택 → ✓완료(딥그린)로 전환 · 축 이름을 작은 라벨로 유지(플로팅 라벨 — "노랑"이 무엇의 노랑인지 셀렉트만 봐도 리뷰 가능) · 값 굵게(600) · 보더 딥그린
· 안내 문구의 조사(을/를·이/가)는 받침에 따라 처리 — "문구을(를)" 같은 병기 금지
· 품절 옵션은 숨기지 않고 흐리게 노출 — 있는 줄 알고 찾는 확인 비용 제거
· 구매하기는 필수 조건 미충족 시 비활성 + 버튼 위에 남은 항목을 지목하는 캡션
· 쿠폰은 시트에서 계산하지 않습니다("주문서에서 적용") — 시트와 주문서 금액이 어긋나면 신뢰가 깨집니다
· 배송비는 예상 결제금액에 합산하지 않고 아래 별도 표기 · 무료배송 임계 도달 시 자동 전환
