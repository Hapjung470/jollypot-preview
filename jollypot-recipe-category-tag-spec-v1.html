한 장 요약

단일 카테고리 트리를 만들지 않습니다. 레시피는 5축 태그 사전 46값 + 보조 태그 8값으로 분류하고, 검색 랜딩은 3계층(상세 → 조합 → 축)으로 자동 생성합니다. 태깅은 AI 추출 시 자동 부여 + 어드민 검수, 노출은 레시피 3건 이상 모인 값만. 동의어 정규화 사전이 시스템의 기반입니다(추출 시점 적용).

0왜 이 구조인가 — 수요의 피라미드 (전부 실측)

네이버 월검색량을 59개 키워드로 조회한 결과, 레시피 검색 수요는 3층으로 갈립니다:

1층 · 메뉴명콩나물무침 101,250 · 김치찌개 78,500 · 미역국 30,910 — 최대 수요. 레시피 상세 페이지의 제목·스키마가 받는다(검색노출 07절). 카테고리가 아니라 콘텐츠의 일이다.
2층 · 조합어두부조림 78,440(> 두부요리 48,210) · 감자조림 68,690 · 애호박볶음 55,970(애호박요리의 2.7배) · 계란찜 48,180 — 재료×방법 교차 랜딩이 받는다. 이 수요 때문에 방법 축이 필요하다.
3층 · 축 이름감자요리 49,340 · 저녁메뉴 38,560 · 이유식 23,070 · 밑반찬 16,680 — 축 랜딩(허브 페이지)이 받는다.

반례 실측: "10분요리" 월 30회 · "에어프라이어레시피" 570(같은 뜻 "에어프라이어요리"는 3,400) — 기획 언어와 접미어 선택을 검색량 없이 정하면 수요 없는 페이지를 만들게 된다.

현재 제목에 셀럽명 3건 실존. 제목·출처 표기(authorName)는 출처 명시라 유지하되, 태그·랜딩 페이지 생성은 금지 — 유명인 성명으로 트래픽을 모으는 페이지는 퍼블리시티권(부정경쟁방지법) 분쟁 소지. 법무 확인 전까지 안전측.

2랜딩 3계층 — 페이지는 태그의 교차로 자동 생성

  1. 1층 · 레시피 상세 = 메뉴명 검색을 받는다 제목·schema.org Recipe(태그를 keywords·recipeCategory로 출력)·검색노출 ON/OFF(07절)로 처리. 이 스펙의 범위 밖이지만 수요의 최대 덩어리가 여기라는 사실이 전체 설계의 전제.
  2. 2층 · 조합 랜딩 = 재료 × 방법(또는 종류) 예: 두부×조림 → "두부조림" 페이지. 새 사전이 필요 없다 — 이미 붙은 태그의 교차 조회일 뿐. 생성 게이트: 레시피 3건 이상 AND 월검색량 1,000 이상(검색량은 어드민에서 조합 등록 시 확인). 게이트 미달 조합은 URL 자체를 만들지 않는다.
  3. 3층 · 축 랜딩 = 태그값 허브 "감자" → 감자 태그 전체 + 하위 조합 링크(감자조림·감자볶음). 노출 게이트 3건 동일.
과분화 방지 — 반면교사 실측
같은 몰의 상품 카테고리: 소분류 140개 중 112개(80%)가 상품 0개. 레시피에서 같은 실수를 막는 장치가 위의 게이트들이다. 태그 사전 54값 × 레시피 158건 = 값당 기대 2.9건 — 게이트가 없으면 절반이 빈 페이지가 된다. 게이트는 협상 불가 요건.

3동의어 정규화 — 추출 시점에 한다

158건 재료 필드 전수 실측: 계란 39건 vs 달걀 7건 · 다진 마늘은 띄어쓰기까지 3갈래(21/15/10건) · 간장 4갈래(34/10/2/2) · 대파 3갈래(23/7/3). 정규화 없이 태깅하면 "계란" 랜딩에서 달걀 레시피가 빠진다.

적용 위치가 중요합니다: 태깅 단계가 아니라 레시피 추출 파이프라인에서 — ingredients에 원문(name)을 보존하고 normalizedName을 병기. 이러면 태깅 · 쿠팡 재료 매핑(158/158건 보유 확인) · 재료 검색이 사전 하나를 공용한다.

5운영 규칙 (어드민 요건)

  1. 태그 사전 = 통제어휘 신설·개명은 운영자만. 신설 게이트 = 콘텐츠 5건+ AND 월검색량 5,000+(보조는 2,000+). 자유 태그 입력 금지. 분기마다 게이트 재심사(승격·강등) — 아보카도가 첫 승격 사례.
  2. 태깅은 AI, 확정은 검수 재료 축=정규화 매핑 전자동 · 나머지 축=분류 프롬프트. confidence < 임계 → 검수 큐(임계는 158건 백필 검수 결과로 확정). MANUAL 태그는 재태깅이 덮지 않는다. 레시피당 상한: 축 6 + 보조 2 = 8.
  3. 노출 게이트 태그값·조합 랜딩 모두 레시피 3건 미만이면 프론트 숨김(어드민에서만 보임). 시즌 태그(명절음식)는 기간 밖 자동 숨김.
  4. 개념 3분리 태그=분류(이 문서) · 그룹=운영 노출 묶음(메인 진열) · 컬렉션=유저 저장(스크랩북). 그룹·컬렉션을 분류 대용으로 쓰지 않는다.

7적용 단계와 확인 필요

P1 정규화 사전 + 태그 스키마 + 추출 파이프라인 자동 태깅 + 기존 158건 백필·검수 → P2 발견 탭 칩 필터(+15분 필터) + 축 랜딩 → P3 조합 랜딩 + 검색노출(07절) 연동 + 대상 축 콘텐츠 수급(이유식·아기반찬 현재 2건).
