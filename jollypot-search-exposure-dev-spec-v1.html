검색노출 개발 요건

v1 · 2026-08-26 · 레몬트리커뮤니케이션
목적: 레시피는 자유롭게 만들되, 검색엔진(구글·네이버)에는 운영자가 고른 것만 보이게 합니다.

✓ 요약 — 레시피에 검색노출 ON/OFF 필드 하나를 추가하고, OFF는 검색엔진에 숨기고 ON만 사이트맵에 넣습니다. 어드민에서 사람이 켜고 끕니다.

1데이터 필드 (레시피 테이블)

필드내용
search_exposureON / OFF · 기본값 OFF (대량등록·AI생성·유저생성 전부)
exposure_changed_by / at바꾼 사람·시각 (변경 이력)
exposure_group소스 자동 기록: youtube / insta / direct / creator (사이트맵 분리용)
⚠ 기존 노출여부(발행/숨김)와는 완전히 별개 필드입니다. 발행 = 앱·웹에 보임 / 검색노출 = 검색엔진에 보임.

2페이지 동작 규칙

대상규칙
OFF 레시피<meta name="robots" content="noindex"> 출력. robots.txt로 막으면 안 됩니다 (크롤을 막으면 noindex를 못 읽어 오히려 등재될 수 있음)
ON 레시피noindex 없음 + 사이트맵 포함
복사본(remix)항상 noindex + canonical → 원본 URL. 어드민에서도 전환 불가
사이트맵ON 레시피만 포함 · exposure_group별 파일 분리(예: sitemap/on-insta.xml) · lastmod는 실제 수정 시각 · 일배치 갱신
자동 OFF레시피가 숨김·삭제·신고 게시중단되면 검색노출도 자동 OFF + 사이트맵 제외
삭제된 ON 레시피 URL410 응답 (404보다 검색 제거가 빠름)
URL레시피 ID 기반 고정 — 제목·카테고리를 바꿔도 URL 불변 · 도메인은 www/비www 301로 통일

3렌더링 요건 — 검색엔진이 봐야 하는 것

  • 에디터 노트·미리보기 댓글(3개+답글)·요리후기는 초기 HTML에 포함(서버 렌더). 클라이언트에서 나중에 불러오면 검색엔진이 못 봅니다 — 이 요건이 빠지면 검색노출 기능 전체가 무의미해집니다
  • 메타 description은 레시피마다 고유 문장(에디터 노트 첫 문장 권장) — "졸리팟에서 ○○ 확인하세요" 같은 공통 템플릿 금지
  • 사이트 내부 검색 결과 페이지(/search…)는 noindex
  • 모든 페이지 self-canonical (utm 등 파라미터 중복 방지)
  • 스테이징·개발 서버는 전체 noindex

4어드민 UI

동작하는 프로토타입: 레시피 목록 — 검색노출 반영안 v1

  • 목록: [검색노출] 컬럼(ON/OFF 배지, 클릭 전환) + [노트] 컬럼 + 필터 2종(검색노출·에디터 노트)
  • 일괄: 선택 ON / 선택 OFF + 주간 ON 한도 게이지(기본 50 · 운영 설정값 · 월요일 00시 리셋 · 초과 시 전환 차단)
  • ON 확인 모달 경고 4종: 에디터 노트 없음 · 유튜브 소스 · 같은 요리명 이미 ON · 한도 초과 — 한도 외에는 경고만, 차단 아님
  • 선택 삭제 모달: ON 포함 시 잔상 경고
  • 에디터 노트 저장 화면: 「저장하며 검색노출 ON」 체크박스
  • 원본 상세: 검색노출 카드(상태 + 판단 참고 + 변경 이력)
  • 대량등록 완료 화면: "검색 비노출로 생성됩니다" 고지 1줄

5이번에 하지 않는 것

  • 자동 품질 검사(자막 유사도 등) · 신호 기반 자동 승격 · 서치콘솔 API 연동 — 전부 다음 단계. 지금은 수동 ON/OFF가 전부입니다

6검수 체크리스트 (QA)

  • OFF 레시피 소스보기에 noindex 메타가 있는가
  • robots.txt에 레시피 경로 Disallow가 없는가
  • 사이트맵에 ON 레시피만 있는가 · 소스별 파일로 나뉘는가
  • 복사본 페이지에 noindex + canonical이 있는가
  • 숨김 처리 시 검색노출이 자동 OFF되는가
  • 댓글·에디터 노트가 자바스크립트 끄고 봐도 HTML에 보이는가
  • 제목 수정 후에도 URL이 그대로인가
