홈 추천 섹션 — 알고리즘 정의서

개발사 전달용 · 룰베이스(비 ML) · 홈 v14-10의 코너 컴포넌트를 재사용하는 자동 추천 섹션 4종의 정의와 구현 방향

전 섹션 기본 OFF — 오픈은 어드민 토글로 jollypot-reco-algo-spec-v1 · 2026-08-03

0. 배경과 결론

어드민 프로토타입 초기안에는 오늘의 추천 레시피 · 인기 급상승 · 테마 컬렉션 3개의 알고리즘 섹션이 데모로 들어 있었다. "이 3개가 고객가치가 가장 높은 구성인가"를 검토한 결과가 아래 표이며, 결론은 2개 재정의 + 1개 제외 + 2개 추가 = 확정 4종이다.

초기안판정사유
오늘의 추천 레시피재정의"막연한 추천"은 히어로 데크(에디터 픽)·화제 코너와 역할이 겹침. 시간대 컨텍스트 추천("지금 이 시간엔")으로 구체화해야 고유 가치가 생김 — 타깃(바쁜 엄마)의 실질 질문은 "지금 뭐 해주지"이므로
인기 급상승유지+게이트가치 있음. 단 초기 트래픽(DAU 수십)에선 "급상승"이 통계적 노이즈 — 볼륨 게이트 미달 시 섹션 자체 미노출 조건 필수. 누적 인기(화제의 레시피)와 구분: 화제=누적, 급상승=최근 변화율
테마 컬렉션제외알고리즘이 아니라 큐레이션. 이미 홈 v14-10의 로테이션 슬롯("이번 주 테마" · 수동 핀)으로 존재 — 중복 구현 금지
+ 새로 올라온 레시피추가UGC 플라이휠의 시동 장치 — 새 레시피가 홈에 즉시 노출돼야 올리는 사람이 생긴다(레시피계의 오늘의집 전략과 직결). 구현 비용 최저
+ 우리집 냉장고 추천추가졸리팟 차별화의 핵심(냉장고 기능 연계). "지금 있는 재료로" — 03 냉장고 트랙의 레시피 매칭 로직 재사용. 냉장고 데이터 있는 유저에게만 노출

1. 공통 규칙 (전 섹션 적용)

  • 후보 풀: 발행 상태 = published AND 검수 통과 AND 미처리 신고 없음
  • 빈 섹션 금지: 섹션별 최소 노출 개수 미달 시 섹션 자체를 렌더링하지 않는다 (레시피 상세 v1.5의 조건부 렌더링 원칙과 동일)
  • 기본 OFF: 4종 모두 어드민 [큐레이션 ▸ 홈 섹션 편성] 토글 기본 OFF 상태로 출고. 코드 배포 없이 토글만으로 ON
  • 표시 형태: 홈 v14-10의 기존 가로 코너 컴포넌트(context-section) 재사용 — 신규 UI 없음
  • 노출 개수: 섹션당 12개 (신규 섹션만 최소 6개)
  • 중복 제거: 같은 홈 화면 안에서 상위 섹션에 이미 노출된 레시피는 하위 알고리즘 섹션 후보에서 제외
  • 파라미터 상수화: 아래 정의의 모든 숫자(윈도우·임계값·가중치)는 하드코딩하지 말고 설정 테이블(reco_params)로 분리 — 운영 중 조정 가능하게
  • 계산 방식: 서버 배치(크론) 계산 + 캐시 서빙. 실시간 쿼리 불필요, ML 불필요 — 전부 SQL 집계 수준
  • 최소 로깅: 섹션 노출(section_impression)·섹션 내 카드 탭(section_card_tap) 2개 이벤트만. 상세 측정 설계는 이번 범위 아님

2. 알고리즘 정의 4종

A. 지금 이 시간엔 — 시간대 컨텍스트 추천

입력현재 시간대 슬롯. 경계는 홈 데크 헤더와 동일 재사용: 아침 05–11 · 점심 11–15 · 저녁 15–21 · 야식 21–05
데이터레시피별 time_slot 적합 태그(다중). 초기엔 카테고리→슬롯 매핑 테이블(운영자 관리)로 자동 부여. 예: 국·찌개·메인반찬→저녁, 도시락→아침·점심, 디저트·간식→야식 외
정렬슬롯 적합 필터 → 최근 30일 저장수 내림차순 → 동률 시 최신 발행순
노출 게이트슬롯 적합 후보 ≥ 12
캐시1시간 (슬롯 경계에서 강제 갱신)
# 의사코드
slot = time_slot(now)                      # 데크 헤더와 동일 함수 재사용
pool = published_pool()                    # 공통 후보 풀
cand = [r for r in pool if slot in r.time_slots]
cand.sort(key=(saves_30d desc, published_at desc))
return cand[:12] if len(cand) >= 12 else None   # None = 섹션 미노출

B. 인기 급상승 — 최근 변화율

정의최근 72시간 저장수가 직전 72시간 대비 2배 이상 성장했고, 최근 72시간 저장수가 최소 5 이상인 레시피
정렬saves_72h 내림차순
노출 게이트조건 충족 후보 ≥ 12. 미달이면 섹션 미노출 — 누적 인기로 대체하지 않는다(화제의 레시피 코너와 중복되므로)
캐시15분
# 의사코드
for r in published_pool():
    grow = saves(r, last=72h) / max(saves(r, prev=72h), 1)
    if saves(r, last=72h) >= MIN_SAVES(5) and grow >= MIN_GROWTH(2.0):
        cand.append(r)
cand.sort(key=saves_72h desc)
return cand[:12] if len(cand) >= 12 else None
왜 게이트가 필수인가 — DAU가 낮은 초기엔 저장 2→4건도 "2배 성장"이다. 임계 없이 켜면 급상승 섹션이 사실상 난수 추첨이 되고, 유저가 섹션 이름을 불신하게 된다. 게이트 미달 시 숨기는 것이 틀린 추천을 보여주는 것보다 낫다.

C. 새로 올라온 레시피 — 최신 + 검수 통과

정의최근 7일 내 발행 + 검수 통과 레시피, 최신순
다양성 규칙동일 크리에이터 최대 2개 (한 명이 섹션을 도배하는 것 방지)
노출 게이트후보 ≥ 6 (타 섹션보다 낮음 — 신규 콘텐츠는 6개여도 가치 있음)
캐시1시간
# 의사코드
cand = [r for r in published_pool() if r.published_at >= now - 7d]
cand.sort(key=published_at desc)
cand = cap_per_creator(cand, max=2)
return cand[:12] if len(cand) >= 6 else None

D. 우리집 냉장고 추천 — 재료 매칭 (유저별)

정의유저 냉장고 재료 집합 F와 레시피 필수 재료 집합 R의 매칭률 match = |F∩R| / |R|이 0.6 이상인 레시피
제외 규칙기본 조미료(소금·설탕·식용유·간장 등 팬트리 상비 목록 — 운영자 관리 테이블)는 R에서 제외하고 계산
정렬match 내림차순 → 유통기한 임박 재료 포함 시 +0.2 가산 → 저장수
노출 게이트냉장고 재료 ≥ 3 등록 유저에게만 섹션 노출 + 후보 ≥ 6
캐시유저별 · 냉장고 변경 시 무효화
# 의사코드
F = fridge_items(user) - PANTRY_STAPLES        # 상비 조미료 제외
if len(F) < 3: return None                     # 냉장고 없는 유저에겐 섹션 자체 미노출
for r in published_pool():
    R = r.ingredients_normalized - PANTRY_STAPLES   # 재료 마스터 ID 기준
    match = len(F & R) / max(len(R), 1)
    if match >= MIN_MATCH(0.6):
        score = match + (0.2 if F & expiring_items(user) & R else 0)
        cand.append((r, score))
cand.sort(key=(score desc, saves desc))
return cand[:12] if len(cand) >= 6 else None
전제 — 재료 마스터 DB. 이 알고리즘은 재료명이 정규화돼 있어야 동작한다("대파"="파"="쪽파❌"). 재료 마스터 1개가 냉장고 매칭 + 레시피 상세의 대체재 치환 + 영양 자동계산 3곳의 공통 기반이므로 개발 착수 시 최우선 구축을 권고. 유일하게 03 냉장고 트랙과 의존 관계가 있는 섹션 — 나머지 A·B·C는 독립적으로 개발 가능.

3. 구현 방향

  • 아키텍처: 크론 배치(A·B·C는 전역 캐시, D는 유저별 온디맨드+캐시) → 홈 API가 캐시를 읽어 섹션 배열로 응답. 프론트는 섹션 배열을 순서대로 렌더링할 뿐, 알고리즘을 모른다
  • 어드민 연동: [큐레이션 ▸ 홈 섹션 편성]에 4행이 OFF 상태로 이미 등재(jollypot-admin-v4-19-3). 토글 ON 시 홈 API 응답에 포함되기 시작. 순서도 같은 화면의 드래그 정렬을 따름
  • 파라미터: reco_params 테이블 — 위 정의의 굵은 숫자들이 기본값. 어드민 [운영 설정]에서 편집 가능하면 이상적이나, MVP에선 DB 직접 수정도 허용
  • 실패 처리: 계산 실패·캐시 만료 시 해당 섹션만 조용히 미노출 — 홈 전체를 막지 않는다
